1. 传输与地址
TCP485 支持 TCP Client / TCP Server 和透明传输。实际部署沿用项目端点，不能使用手册中的示例端点替代。
RS485 参数：9600 baud，8 数据位，无奇偶校验，1 停止位。
普通控制帧固定 5 个二进制字节：AE ID CMD VALUE EE。
不是 ASCII 字符串；手册没有在此帧中定义校验和。
设备地址旋钮为十六进制；项目 Device ID 也按十六进制解析，例如 "15" -> 0x15。
ID=00 是广播地址。首轮实现禁用广播及模块参数修改。

2. 开关 GT-C8-RL（通道 c=1..8）
开：AE ID c F1 EE；关：AE ID c F2 EE。
翻转：AE ID (A0+c) F1 EE。
查询：AE ID (A0+c) F2 EE。
反馈：AE ID (D0+c) F1/F2 EE，分别表示开/关。
主动反馈模式由 C7/C8 查询/设置；设置须连续发送 3 次。初始实现只查询状态，不改模式。

3. 调光 GT-E4-RL、GT-D8-RL、GT-L8-RL
GT-E4 通道 1..4；GT-D8/GT-L8 通道 1..8。
立即设置：AE ID c level EE。
渐变设置：AE ID (B0+c) level EE。
level 为 0..100 的整数二进制值，100 对应 0x64，30 对应 0x1E。
查询：AE ID (A0+c) F2 EE。
反馈：AE ID (D0+c) level EE。
暂停渐变：AE ID (A0+c) 05 EE。
项目调光模块 11..15 均有 8 通道，不能直接配置成 4 通道 GT-E4；具体是 D8 或 L8 尚须核对实物。
模块内部渐变速度由 C1/C2 设置，未确认与 Control4 Ramp Timer 的对应关系。
场景的指定渐变时长需单独实现或验证，不能直接把毫秒写入 level 字节。

4. 电机 GT-M4-RL（组 c=1..4）
升：AE ID c F1 EE；降：AE ID c F2 EE；停：AE ID c F0 EE。
手册未提供位置查询/位置反馈。区分发出的动作与已测得位置，不能伪造百分比状态。
硬件互锁输出时长由 C1/C2 查询/设置。保持原有设置。
窗帘的升/降与开/关方向需实物验证。

5. 面板 BT-86-C（按键 c=1..6）
按下：AE ID (D0+c) F1 EE；松开：AE ID (D0+c) F2 EE。
LED 开：AE ID c F1 EE；LED 关：AE ID c F2 EE。
按键反馈与开关状态帧相同，按已导入的设备地址和类型解释。
LED 控制要求面板手动模式 C8 02；出厂自复位模式 C8 01 不接受 LED 控制。
不自动修改面板模式。现有项目有 Rocker 等面板类型，需核实实际按键数/布局再套用 6 键模型。
长按、双击等事件应在软件中依据按下/松开计时实现，并核对现有 Control4 程序语义。

6. 接收器与重连
TCP 可能拆分/合并帧，使用缓冲区按固定 5 字节解码，验证起止字节。
ID/VALUE 可能等于 AE 或 EE，不能按结束字节直接切分。
错误帧逐字节重新同步，保留未知模块/未知命令日志。
CC 固件查询返回 ASCII，暂不混入普通状态轮询。
连接断开后状态标记为未知；重连查询开关/调光状态，不自动重放过期动作。
共享总线应由一个发送队列串行写入；发送间隔可配置，手册未规定可靠的最小间隔。

7. 导入与验证范围
hb-device-map.json 保存 Control4 对象、房间、十六进制地址和通道映射，不含授权密钥。
可复用已解析的 68 个灯光场景与 215 个事件程序，但程序转换需要按命令/条件类型逐项覆盖。
首先离线测试编码、分包/粘包、错误帧和地址分类，再只读查询真实网关。
离线可证明编码符合文档；不能替代硬件联调。
EA-5 媒体、Control4 App 和 SR-260 并非这些 RS485 手册所覆盖的功能。

8. 2026-10-13 原生翻转补证
用户提供的 AD8-DIN(RS485) Ver2.2.1 与 R8I8-DIN PRO.(RS485) Ver2.7.7 原始手册仍在本机资料目录。
原文件 SHA-256 与 reference/manifest.json 中清理时记录一致；未恢复仓库中的整份手册。
AD8 第 7.4 节、R8I8 PRO 第 7.3 节均明确单路翻转：AE ID (A0+c) F1 EE，c=1..8。
单路查询仍为 AE ID (A0+c) F2 EE；只使用单路命令，不启用广播或全路命令。
GT-E4、GT-D8、GT-L8 原始手册亦列相同翻转格式。
翻转是相对操作，不能由旧缓存猜目标值，不能用绝对状态反馈伪称命令确认；断线或超时不自动重发。
AD8 手册没有说明翻转开启后恢复哪一亮度，须读取实际结果，不能假设全亮或场景目标亮度。
此核对仅证明文档报文定义；本次没有发送真实翻转指令，不能当作实物通过。

9. 2026-10-13 整模块只读查询补证
用户建议按模块一次查询全部8路。已再次核对原始PDF文本与命令表页面：
AD8-DIN Ver2.2.1 第7.6节明确8路查询 AE ID A0 F2 EE，亮度反馈按 D1..D8 分路，值为0..100。
R8I8-DIN标准版 Ver2.2.5 第7.3节明确全部查询 AE ID A0 F2 EE，第8路单独查询为 AE ID A8 F2 EE；反馈按 D1..D8 分路，F1/F2为吸合/断开。
R8I8-DIN PRO Ver2.7.7 第7.3节把全部查询写为 AE ID A8 F2 EE，与前一行第8路重复。结合标准版及AD8格式，A0很可能是正确候选，但不能把同系列旁证当作PRO硬件已验。
这里ID必须是实际单模块地址；ID=00广播仍不启用。整模块查询和模块全部开关控制是不同操作。
固定1cd94a4基线编码器只支持单路Query；后续整模块编码及聚合刷新仍为待验证草稿。第8节的单路限制是当时实现范围，不表示AD8手册不支持全路查询。
整模块反馈的时序、是否完整返回和实际固件能力尚未实测；手册没有承诺8路原子快照或查询事务ID。
规划按gateway、module地址及已核对profile聚合，逐启用绑定保留boot/连接代次、新鲜度及命令完成门禁；未回通道保持未知，未绑定通道不得据此建立受控设备。
模块聚合可以减少发送请求，但不能单凭请求数推断5秒新鲜度通过。须重测完整96端点、部分反馈、分包/粘包、错模块、重复帧、超时、重连及控制抢占。
原文件SHA-256与reference/manifest.json相符；没有恢复仓库中的手册或发送真实Query。摘要见 docs/evidence/stage-d-study/module-query-protocol-source-check.json。
