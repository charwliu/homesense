# NanoPi HomeSense 主服务器

NanoPi R6S 运行 `homesense-e2.service`，NGR 为手动冷备并接收定时数据备份。任何时刻只允许一个现场总线执行器与同一组 HAP 身份运行，不自动故障切换。

## 入口与接线

| 项目 | 配置 |
| --- | --- |
| 管理 HTTPS／WSS | `https://homesense.lab.vixal.xyz:8444` |
| DNS | `homesense.lab.vixal.xyz` CNAME → `nanopi.lab.vixal.xyz`；A 为 `192.168.3.3`／`192.168.4.4`，AAAA 使用两侧当前前缀及固定后缀 |
| VLAN3 | 核心5号 Access3 → R6S wan，`192.168.3.3/24`，IPv6 后缀 `::3:3` |
| VLAN4 | 核心6号 Access4 → lan1／br2，`192.168.4.4/24`，IPv6 后缀 `::4:4` |
| 默认 IPv4 出口 | 经 br2 到 `192.168.4.253`，保留 A 线备用路由 |
| 485 网关 | `192.168.0.10:8443`，经 VLAN4 访问 |
| HAP | 单座「HomeSense」桥，保留 `study-e` 内部身份与配对，监听 `.3.3:51828` |
| NGR 冷备 | `.3.2/.4.2`，HomeSense 服务禁用，主角色门禁关闭 |

R6S 与核心23号口的 NanoPi5 路由器是两台设备。服务器双网卡不桥接 VLAN3／4，不提供 DHCP、RA 或跨 VLAN 转发。系统使用 microSD 启动。

主程序监听 `.3.3:8444`，`systemd-socket-proxyd` 为 `.4.4` 与两侧 IPv6 提供同一 TLS 服务入口，不增加第二个执行器。配置、DNS与前缀维护见[附加监听](web/README.md)和[网络配置](../../docs/network-configuration-runbook.md)。

## 文件与运行身份

生产根目录为 `/home/alarm/apps/homesense`：

| 位置 | 用途 |
| --- | --- |
| `releases/` | 当前及最近一个可执行回退版本，均为本机交叉编译的 ARM64 Cargo Release |
| `service/config/` 及服务单元指定配置 | 设备／自动化启动配置与 HAP 计划；实际活动版本以持久配置为准 |
| `service/state/` | 配置、审计、配对、AID／IID、App 凭证与权限等运行状态 |
| `service/tls/` | 服务证书链与私钥；私钥权限600 |
| `service/secrets/` | 服务启动凭证，不随普通 ELF 更新替换 |
| `/var/lib/homesense-role/primary` | root 管理的主角色门禁 |

通过 `systemctl cat homesense-e2.service` 和实际进程核对入口、运行路径与参数，不从文档中的固定发布目录猜当前制品。维护记录逐项保存源码指纹、Release profile、架构、文件大小与 SHA-256；实际配置、凭证和验收日志不入库。

## App 与 Apple 家庭

App 家庭页使用 HomeKit，选择已授权家庭即可控制。管理功能在“配置管理 → 服务连接”填写 HTTPS 域名入口与令牌；证书须受系统信任且匹配域名。需要私有 CA 时只安装公开根证书，不分发服务私钥。

管理凭证按服务地址与端口保存到各台设备的本机 Keychain。换地址时使用原授权令牌连接，无需删除 Apple「家庭」桥或重新配对。当前桥显示名称为「HomeSense」，配件归房使用[App 房间管理](../../apps/HomeSense/README.md#apple-家庭房间归属)。

## 发布与只读验收

1. 在开发本机完成必要定向及回归检查，用 `--release` 交叉编译 `aarch64-unknown-linux-gnu` 生产 ELF。
2. 固定并核对制品、配置范围和回退清单；只上传运行必需的生产 ELF 及明确授权资料，不上传测试文件或源码。
3. 做完整冷备，设置独立于发起进程的恢复守护，再短停服务并切换。
4. 核对服务身份、架构、HTTPS／WSS、配对与权限、HAP 图以及两轮12模块96路反馈；队列静止须连续观察，不能用瞬时空队列判定完成。
5. 验收成功后提交并解除守护；失败保留失败状态并整套回退。稳定后只保留当前与最近一个可执行回退版本。

目标不运行完整测试，部署验收不发送灯光、窗帘或风机命令。日志、备份与失败证据分别保留，详见[完整状态回退](../../docs/state-upgrade-rollback.md)。

## 手动恢复边界

[定时备份](backup/README.md)不会覆盖 NGR 生产状态或自动启动冷备。恢复点使用最新成功快照，并核对其程序及数据库格式。

1. 停止并禁用旧主服务、关闭主角色门禁；旧主失联时确认断电或隔离总线，不能只凭 ping 失败启动冷备。
2. 在目标保持停止时备份原状态，恢复选定的完整数据库、控制器 ID、凭证和活动配置，保留最新身份与撤销信息。
3. 将 HAP 计划和保存的监听地址对应到新主，保持不可变身份与配对；核对域名 DNS 只指向实际可用入口和匹配证书。
4. 设置独立恢复保护，开启唯一主角色并启动服务，进行 TLS、凭证、HAP 与96路反馈的只读验收。
5. 回切使用相同的“先停旧主、复制最终状态、再开新主”顺序。

NGR 使用 x86_64 Release，不能运行 ARM64 ELF。冷备不是实时副本，不能只恢复部分数据库或在两个主机同时广播同一身份。
