# 审核后的场景停用链接

停用执行的是独立目标场景的完整激活向量。它不是取消运行、源成员全关、源电平反转、源与目标并集，也不执行目标自己的停用动作。来源和目标均可为 Immediate 或 Timed；目标的步骤次序、延迟、渐变、设备及来源保持不变。合成验证包含不重合的 4 路来源与 36 路目标四种组合。

## 显式表达与默认挂起

运行时文档可增加如下审核链接；源和目标定义须单独审核并启用。源已有传统 `deactivate` 向量时不得再添加此链接，避免两种含义混用。

```json
{
  "scene_deactivations": [{
    "scene": "source",
    "target": "target",
    "enabled": false,
    "review_evidence": "独立审核依据",
    "active_execution_policy": "require_quiescent_runtime"
  }]
}
```

Control4 转换契约需独立声明 `deactivation_runtime`，其中包括同一策略及非空审核依据。精确的原 `toggle_id` 必须在同一 Agent 解析到目标。目标时序单位、锚点、rate/backend、编码及绑定仍需要原有逐字段审核。转换输出的定义、链接和程序默认全部禁用；不能仅启用调用规则绕过源、目标和链接的审核。缺失、未知、过期、未支持的效果使整个场景及其依赖挂起，不生成源语义默认值。

## 首项策略的范围

`require_quiescent_runtime` 是通用的、显式受审的保守策略，不是任何原项目的默认行为。准入所在线程检查本次 boot／配置版本的全局控制工作：

- 任一 Pending／Running 场景执行器（包括源、目标和其他控制者）；
- Accepted／Writing 控制命令，包括已过期但未结算的工作；
- Uncertain 控制回执。

纯 Query 回执不属于控制工作，排队或写入中的后台状态查询不阻挡停用。检查依据为真实持久化生命周期及命令意图；不根据灯光电平、场景名称或未确认物理状态猜测任务是否结束。未结算记录不会被此路径删除、取消、置成功或自动重放。任一同批源激活与停用冲突也拒绝。

静止校验与变量、命令及目标 Timed 回执在同一准入 owner 的无 await 临界段内完成；真正接受的数据仍由既有事务整体提交。拒绝时不产生新变量值、输出、目标运行或取消记录，其他控制者的工作保持原有生命周期。此策略不提供源运行中“取消后停用”或“继续并行停用”的语义；这些策略须另行审核与实现。

## 执行、预算与恢复

合格 `DEACTIVATE_SCENE` 保留来源 Agent、调用位置和原条件。未选中分支不执行静止守卫。选中分支按目标激活展开，附带可信守卫及目标来源，进入原有真实变量、权限、配置代次、因果链和准入路径。Immediate 目标产生真实命令回执；Timed 目标创建以目标为 definition 的真实运行，并保留源停用调用为 causation/source。延迟、渐变并非零时延近似；停用链路的未来渐变样本也在接受前计入因果预算。

接受并不代表物理完成。取消目标运行使用原来的取消契约；已写出的输出不回滚、不补偿。目标已有完成写出的步骤、随后步骤失败时，场景运行保留 Partial 和实际命令来源；单帧未完整写出则保留 Uncertain 回执并使传输失败关闭，后续停用可被拒绝为 Runtime(ServiceCommunicationFailure)，不强行归类为静止守卫 Busy。重启将未结束记录标为 Interrupted，旧命令及渐变样本不重放。静止守卫拒绝与接受后结果不确定仍保持既有区分，未放宽 fail-closed 规则。

HAP Immediate 动作的 false 写入仍是瞬时动作的 no-op；只读 Activity 仍只读。现有 Native 互斥组 provider 和选择证据契约保持原样。新停用链接用于明确的程序 Scene(false) 调用，不借用 HAP false 来改变入口语义。

该实现不批准或启用原源场景、事件及变量，不证明阶段 D/E 完成，不改变 EA-5 配置及控制范围。
