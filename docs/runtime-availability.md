# 持续服务与网关恢复

已建立服务的网关断连、周期查询超时或恢复同步失败，不作为正常停服条件。HTTPS／WSS 保留会话与诊断，HAP 保留配对身份；受影响设备、场景及控制按实际就绪状态显示未知或不可用。

## 故障处理

- 使失效连接的旧反馈与待决证明过期，不把历史读数当实测。
- 使用有界退避重连，记录缺失的模块／通道、连接代次和失败范围。
- 重连后按新代次同步登记的可读输出，达到就绪条件后仅接受新请求。
- 不重放旧灯光、窗帘、相对翻转、已取消时间线或启动动作。
- 诊断、恢复队列和日志保持有界；显式停止和整体测试截止仍及时结束。

独立网关的状态和可用性分别报告。某类入口若需要更大范围的同步证明，须继续满足其实际准入门槛，不能仅凭管理接口在线就宣称所有负载可控。

存储损坏等不可恢复错误与网络恢复分开报告，不能吞入无限重连。状态同步、查询退避及告警规则见[查询与推送](adaptive-query-refresh.md)，运行和停止方式见[服务生命周期](service-lifecycle.md)。

## 定向验证

在开发本机使用生产 CLI 与模拟网关，验证无反馈／断连期间接口、控制拒绝、部分反馈门禁、完整新代次恢复、停止和资源上限。多网关隔离、HAP 身份保持及新请求执行须各自断言，不以单网关存活替代多网关验证。现场长期稳定性按[结项清单](control4-takeover-checklist.md)持续观察。
