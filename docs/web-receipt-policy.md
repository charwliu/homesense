# Web 请求账本、端点作用域与过期策略

服务端按已认证 principal、规范化端点和请求键保存执行记录。端点来自服务端路由，不能通过请求 JSON 或自定义端点头覆盖。控制写请求沿用 body.request_id；管理变更使用 Idempotency-Key 头。同作用域同键同内容返回原记录，异内容返回冲突；过期不是再次执行许可。服务器 boot、当前时钟不属于请求内容，重启不会制造内容冲突。新执行仍经过原有权限、配置版本、Origin、CSRF 和能力校验。

## 配置与首期策略

在实际服务状态目录放置 web-receipt-policy.json：

```json
{"max_records":100000,"expiry":{"kind":"never"}}
```

或明确选择标记过期但完整保留记录：

```json
{"max_records":10000,"expiry":{"kind":"mark_expired_preserve_fence","window_ms":86400000}}
```

文件缺失采用原有 100000 条容量和永久保留默认。容量范围 1–100000，保留原实现的上限；窗口范围为明确毫秒的 1ms–365天，是通用输入边界，不是 Control4 rate 单位。未知策略、未知字段、越界及超过 4096 字节的配置拒绝启动，不回落默认。模拟和 TCP 管理服务在启动动作释放前验证并捕获策略，真实 API 使用该已验证快照；不是仅增加 CLI 参数。管理员诊断显示当前策略。

两种策略都不删除旧键或执行记录，不释放动作容量。容量减少到已有记录数以下仍保留所有历史，已有请求可查询，新键拒绝。其他删除、键复用、自动重试策略未实现且拒绝输入。

新记录保存服务端 UTC 毫秒和确定的截止时间；首次经 claim 或 lookup 判定过期时，与时钟高水位在同一事务持久保存。时钟回拨、进程重启、改回 never 或扩大新窗口不能使旧条目回活。高水位之前的新请求拒绝；已有记录继续可查询。过期记录保持完整原响应，通过 x-homesense-receipt-state: expired_preserved 标示。模块查询和配置发布的 early lookup 同样保留标记；取消请求还用 x-homesense-start-receipt-state 标明已过期的来源记录。过期时迟到的原请求结果可补入原条目，但不能变成 New。

## 写接口覆盖

| 类别 | 请求身份与执行记录 |
| --- | --- |
| 设备、模块命令、模块 Query、场景动作、相对动作、取消 | 各自固定规范端点；body.request_id；真实运行或命令回执保留 |
| 配置激活 | 解析后的草稿 UUID；原请求记录可在活动版本变化后读取；不再次发布 |
| 草稿创建／保存、元数据、设备绑定、电机校准、模块绑定／校准／迁移／替换、房间编辑、归档 | Idempotency-Key；各操作与解析后的源 UUID 为规范端点；保留原不可变草稿、所有权、冲突与 tombstone 校验 |
| 历史配置恢复为草稿 | Idempotency-Key 与规范版本端点；只重用原恢复记录，不创建第二份草稿 |
| 凭证签发、修改、撤销 | Idempotency-Key；独立规范端点；保留范围、CAS、所有权和最后管理员保护 |

管理内容摘要采用规范 JSON 的 SHA256，不把提交文档或凭据头存入摘要。凭证范围集合按已解析类型规范化。结果查询可通过同端点、原键、原内容重取原执行记录；未知请求明确 retry=false。用户若要发起新的动作，必须明确使用新键，客户端不自动替换失败请求的键并重试。

凭证 secret 只在第一次成功响应中披露；账本只保存签发 id、grant、状态和已披露标记，重试不再次披露，也不生成新凭证。持久凭证库仍只保存摘要。凭证结果没有秘密字段时，前端明确提示查询原记录。管理账本响应上限 68KiB，容纳原有 64KiB 凭证输入及结果封装；控制回执保持原有 8KiB 上限。

会话登录／退出属于独立鉴权协议，不把 cookie、CSRF 或登录 secret 保存为可重放响应。登录保留现有会话期限及限制，退出只撤销传入的会话。GET、配置预览、只读备份检查不执行配置或设备变更；只读检查不因使用 POST 载体而生成可重放管理动作。

## 格式升级、备份与回退边界

账本采用独立格式 3，不改变控制数据库的 schema。原格式 0 表事务迁入 web_receipt_legacy，原 principal／key／fingerprint／response 原文不变，端点和时间保持未知；它们是跨端点屏障，不能猜测起点、重置或当成新请求。新的端点记录在 web_receipt_scoped；先前内部视图格式 2 可事务升级，所有截止、过期、响应和高水位保持。未知格式和不完整结构拒绝打开，升级失败回滚。

web_receipt 名称保留为索引守卫。原版本 CREATE TABLE 初始化在该名称处失败，阻止旧管理服务启动；不能仅让旧控制写失败而让旧凭证／草稿接口继续绕过账本。兼容读取通过新版 API 查询两个完整集合；旧 SQL 表名不能继续作为表／视图查询。

升级后保持完整账本文件及 WAL 一致性，使用 SQLite 一致性备份；格式 3 备份恢复仍保留旧键和守卫。配置版本回退不会替换该账本。不得单独恢复升级前账本、删除它或换空文件来运行旧程序；这些不是本实现支持的回退路径，不能保证保留新动作的拒绝重放记录。

接受、写出、不确定及未完成请求均不被过期清理移除。请求 future 被取消或完成记录写入失败，原条目保持 Unknown／Reserved；真实执行可能已发生，因此重复请求不会再次进入控制链。此功能不批准原场景、变量或设备语义，不修改 EA-5 控制范围，也不宣称 D/E 已完成。
