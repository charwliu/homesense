# HAP 条件灯光配方

`scene_tracking.hap_action.readback: "reviewed_conditions"` 用于带共享通道、条件分支或既有模式变量的灯光程序。状态仍按 `aggregation: "all"` 从真实设备反馈计算；程序变量不能代替灯光反馈。读取、发布状态本身不会查询或控制总线，未知、待确认或任务过期仍显示不可用。

开启和关闭使用不同的隐藏立即配方，同房间、同范围，不直接调用原相对开关程序。每份配方只能使用原程序已有的设备、变量及变量赋值表达式，以及立即灯光或LED命令；条件可以读取原程序范围内的设备和变量。禁止新增目标、赋值、间接场景调用、查询、窗帘命令和渐变。读回条件必须包含正向灯光条件，只能引用原程序实际控制的灯光，不能忽略条件来扩大“开启”的含义。

这些校验限定控制范围与操作，不证明条件分支的语义。每个候选必须独立验证明确开启、重复开关、当前不匹配时的关闭、模式切换、保留非零亮度、共享通道、未知反馈与LED联动。不得把“关闭未开启场景”直接改成关闭整个共享范围，造成其他模式熄灭。

原 `all_conditions` 继续只接受完整、平坦的绝对灯光向量；`any_lamp` 保留房间“全部”的任意灯亮规则；`confirmed_component` 继续要求原组件的实际执行与反馈证明。新规则不替代这三种策略，也不改变App及墙键的原程序或调用者权限。

无设备反馈触发规则时，运行时不额外保留已完成的空闲因果会话，避免普通操作占满反馈会话容量。存在设备变化规则或反馈缓存变量变化规则时，仍启用原有反馈归因、会话容量和链预算；待完成的定时场景及同步变量级联继续由原会话负责。
