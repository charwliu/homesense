# 场景状态推断规则

2026-10-15 用户确认：按灯的开／关组合推断场景开启；仅在该组合对应多个不同场景时，再用可靠亮度反馈区分。亮度单独显示，唯一开关组合不要求亮度等于场景目标，便于点一次关闭当前亮灯。

亮度未知、过期或不足以唯一匹配时，不猜选场景。后续实现须按模块可读回的实际量化值核对目标，保留实测与历史／目标的区别；具体比较行为须由独立候选和测试验证。

原剩余65场景中已识别4组、10个具有相同开关组合而目标亮度不同的场景，已生成离线计划。全零重复场景不纳入亮度区分。此为新迁移规则，不推断原 Control4 tracking／rate 编码，不等于批准每个场景的完整原程序或物理绑定；未发布配置或启用规则。见[来源核查](evidence/stage-d-study/scene-ambiguity-policy-root-check.json)。

独立源码候选新增显式策略 `power_pattern_then_profile_level`。原 `unique_light_on_pattern` 保持原行为；既有配置不会自动改用新策略。先要求完整、新鲜、无未决输出的开关组合：唯一组合直接选中，不要求亮度等于目标；组合碰撞才读取区分候选所需的调光通道。全关优先归零，不以重复的全关场景猜选成员。亮度缺失、过期、不能唯一匹配，或组合灯供电反馈未知／过期时，保持未知；供电关闭时旧亮度不能选中亮灯场景。

候选首版的亮度区分限于 AD8 已建立的整数百分比读回域，使用精确读回值，不设置通用容差。其他模块若只用于唯一开关组合不受此限制；若需要它的亮度区分碰撞，则启用配置校验拒绝，须先补充该模块明确的读回换算依据。状态推断只建立当前连接的临时投影，不重写历史选择，不证明 EA-5 场景变量；已审核的 LED 联动继续单独接纳和审计。

物理推断已完成纯匹配器、准入／反馈租约及多面板 LED 的合成与实际运行回归。启用仍须逐组审核配置；软件验证不等于完整原程序语义或全屋硬件验收。

支持审核后的 `reconciliation.omitted_targets: "preserve"`：每个场景只操作原定义明确包含的灯，不再为其他成员才涉及的灯补发关闭命令。缺省或 `"off"` 保留原来的组内完整向量行为；策略只有在该组启用物理推断后生效，不自动修改现有配置。状态推断仍采样整个已审核成员并集，缺失／过期反馈保持未知；场景定义省略目标与缺失硬件反馈是两回事。

保留省略目标的多个模式可能同时匹配；这时不按顺序猜选。启用亮度细分时，仅用所有冲突候选都明确指定、且确有差异的亮度通道区分，不把省略亮度当零。该策略的亮度细分只允许已建立读回域的 AD8。原生未知场景也仅为本次成员的目标采样和规划控制，不能套用首个成员的输出范围；完整新鲜投影、权限、截止和不重放保护保持。此增量已通过完整软件兼容回归，配置启用及硬件效果仍分别验收。
