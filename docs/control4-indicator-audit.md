# Control4 场景与面板指示灯核查

`homesense-import` 的只读报告中的 `indicators`，用于复核场景在多个面板入口上的 LED 关联。它读取原始 XML 的程序树，不运行驱动 Lua、不修改 EA-5，也不生成已启用的联动配置。

在已忽略的私有目录中保留报告，文件包含家庭设备标识、事件结构和来源指纹，不能提交到公开仓库：

```sh
umask 077
mkdir -m 700 deployment/ngr/private/indicator-review
cargo run --locked --offline -p homesense-import -- /path/to/project.c4p > deployment/ngr/private/indicator-review/project.json
```

使用新目录保存每次复核，保留原报告。XML 也可作为输入；压缩包、大小和节点限制沿用导入器。报告保留场景、程序和未支持节点，指示灯盘点不能替代语义处置。

## 证据结构

- `actions`：场景激活／停用及已识别面板的 LED 开／关指令；记录事件、代码节点、有效源启用状态、条件和容器路径、报文载荷指纹。动态参数、场景参数与 owner 不一致、超出六键配置的 LED 均留下诊断，不生成目标绑定。
- `candidates`：同一事件、同一词法分支／容器内的场景激活与 LED 开启集合。只统计有效启用的源节点；父节点禁用时子节点也排除。LED 关闭指令保留在原动作中，不作为当前场景的选择指示灯。
- `comparisons`：同一场景不同入口候选集合的并集、交集及差异。缺少 LED 的入口也计入比较，不能静默补成其他入口的集合。

条件节点保存载荷哈希，容器路径包含源位置和祖先代码 ID；Else、不同条件以及名称相同但位置不同的容器不会合并。报告不复制显示文字或激活密钥。

同一个容器激活多个场景，或同一个 LED 同时出现开／关写入时，标为歧义，保留原动作但不猜测 LED 关联；歧义候选不参加集合比较。没有检测到差异也不证明绑定已正确：词法共现无法证明条件可达、设备型号、按键含义、最终运行行为或驱动内部动作。

## 审核与运行时的边界

全部输出 `enabled=false`。集合并集是检查遗漏的线索，不能自动成为修正集合；集合交集也不能当作完整关联。审核时须核对原分支、灯光最终目标、各面板键用途和已有复位指令，再显式填写 `indicator_links` 的审核依据及逻辑设备绑定。

已审核运行时联动采用[灯光状态与 LED 联动](state-and-indicator-policy.md)的约束：场景原本应亮的任意一路关闭，取消对应选择并清除全部关联 LED；原本应关的灯不参与判断。只关闭选择指示，不运行其他灯的物理关闭序列。无法确认的候选继续挂起；EA-5 配置和控制范围保持不变。
