# 离家按模块关灯

后端提供原生 App 可调用的离家管理 API 和可显式发布到 Apple 家庭的“离家全部关灯”动作；Web 管理页面已按用户要求取消。原生入户面板入口及模块批量全关已有现场验证；新增的有界重试与执行结果推送已完成软件隔离资格及程序更新，仍不能用原批量全关现场验收替代新故障路径的现场复验。该操作不会自动改写、启用或合并已导入的 Control4 场景。原有普通灯光、窗帘和场景入口保持原来的语义。

## 有界执行与结果推送

服务端把一次离家请求作为独立逻辑操作，最多三轮模块关闭，轮间隔200毫秒，总期限五秒。实际写出后的回复窗口最多一秒，与已收到反馈的五秒有效期分开；查询确认每次最多250毫秒，原查询重试合计最多500毫秒，不再额外叠加一次主动回复等待。发送排队仍有独立的两秒上限，且所有阶段均受更早的操作总期限限制。只对尚未确认关闭或又收到开启反馈的模块建立新回执，不续期或重放原票据。已确认关闭、仅反馈变旧的模块只补读，不重复发送关闭。查询和控制仍共用唯一总线所有者，显式安全停止保持优先。

尚未轮到发送的串行查询不算设备回复超时。查询已完成或超时也不代表负载关闭；成功仍须全部物理输出真实的写后关闭反馈。整模块应答作为连续报文接收，短暂静默后可以让出查询槽，不再因一个静默通道锁住整条总线五秒。App沿已有WSS接收最终失败和准确缺失范围，不自行重发。

六键和独立API的接受回执共用执行策略，`server_retry`报告最多3轮、轮间隔200毫秒、回复窗口1000毫秒和总期限5000毫秒。确认／失败终态更新后会主动唤醒所有已订阅的状态推送客户端，避免等待下一次500毫秒状态检查；每次唤醒仍重新验证当前凭证、运行配置和允许的结果范围。订阅关闭时恢复原周期检查，避免忙循环；普通推送保活与总线扫描周期保持。

隔离模拟器在每个模块回复前随机等待3～20毫秒，同模块所有应答合并为一次流写入，不逐通道附加等待。9600／8N1下，八个五字节帧连续传输约41.7毫秒；这只是线速占用，不是额外处理延迟。故障通道直接不回复。该模型不改变R818仍须逐通道查询的已知协议范围。

三轮耗尽后，如果已确认关闭的健康模块反馈过旧，在原总期限内只补读这些模块，再冻结失败通道；不增加第四轮，不刷新旧反馈的时间戳。期间收到完整、真实的新关闭反馈仍可确认成功；人工覆盖、撤权、配置或传输变化仍可终止。总期限到达时按当时可证明的真实范围报告，不能把未回复视为已关。最终失败范围冻结后，后来的反馈只更新当前状态，不改写历史结果。

完成指示要求所有原始物理输出都有相应写出之后的新鲜关闭反馈，供电继电器关闭不能代替调光输出归零；未确认、失败或取消均不得发送成功指示。客户端只订阅进度与结果，不自行重发。此增强已完成完整平台软件资格及程序更新，部署后的故障路径现场复验尚未完成。详见[软件资格与更新记录](evidence/stage-e-browser/away-response-refresh-qualification.json)。

## 配置与边界

自动化文档缺省没有 `away_off`，因此按钮隐藏、操作不可用。启用前须审核每个模块的全部八路用途、全部绑定存在且启用，并明确每路设备 ID。默认仅限照明；本次用户明确允许设备间 0x01 第2路排气／风机一同关闭，这是单路授权例外，不扩大到其他非照明负载。未获明确授权的混用负载、缺失绑定或未知通道的模块不得整模块关闭；不支持的型号也不会退回逐路控制。

```json
{
  "away_off": {
    "enabled": false,
    "hap_expose": false,
    "review_evidence": "operator review of the complete lighting operation",
    "active_execution_policy": "cancel_affected_lighting",
    "modules": [{
      "module_id": "lighting-module",
      "devices": ["lamp:1", "lamp:2", "lamp:3", "lamp:4", "lamp:5", "lamp:6", "lamp:7", "lamp:8"],
      "review_evidence": "all eight physical ports verified as lighting"
    }]
  }
}
```

这只是配置片段，须通过已有草稿／预览／发布流程和正常配置校验；审核完毕后才可显式设为 `enabled: true`。模块按稳定 `module_id` 解析当前地址；地址零仍被拒绝，普通 `Channel` 仍禁止零。模块控制只支持确证的 R8I8-DIN PRO 和 AD8-DIN，分别为有地址的 `AE ID 00 F2 EE` 与 `AE ID 00 00 EE`，不会使用广播或渐变全关替代。

`cancel_affected_lighting` 会原子替代受影响设备的排队控制，阻止旧时间线与渐变在随后重新点亮这些灯；其他负载和电机 STOP 不被取消，已经写出的命令无法回滚。另有显式 `require_quiescent_runtime` 较窄策略，有未完成控制或场景时拒绝，不能把它当作主要离家操作的等价实现。

## 权限与执行

主体须有全部受影响照明负载的控制权限。组合灯的隐藏供电继电器仅从完整逻辑灯权限推导；单独授予隐藏继电器不能越过其逻辑灯权限，禁用或缺少任一逻辑所有者也不展开。此范围推导在准入和每帧写出前重新计算。局部房间权限无法借离家入口扩大范围；凭证撤销、授权变更、会话过期及配置变化会在排队写出前重新校验。模块作用范围在排队和写出期间阻挡冲突控制；原生 STOP 优先级保留。

每个模块每轮只有一条物理控制命令；受影响八路的不可变审计与接受、旧命令取消同事务提交。Written 仅表示本机流写完，不等于物理灯已关闭。状态、场景和 LED 继续由真实反馈更新；零反馈保留原非零亮度记忆。部分写出按不确定结果结束连接，恢复不重放旧操作。首版离家审计使用 schema26，现行面板完成提示使用 schema27；旧版本程序应拒绝直接打开新库，回退需使用匹配备份并保留最新配对与撤销状态。

接口为 `GET /api/v1/away-off`（当前主体可用性）和 `POST /api/v1/away-off`。写请求体只包含当前 `revision` 字符串与 `request_id`，不接受客户端给定模块／通道／审核内容。使用既有 HTTPS、Host/Origin、会话／Bearer 和 CSRF 约束；请求键持久化，未知结果不会自动重试。

## Apple 家庭发布

`hap_expose` 缺省为 `false`，须在相同审核配置中显式启用。每个桥只在自身已发布灯光覆盖完整操作范围时添加“离家全部关灯”；部分桥不会借其他桥或 Web 管理员的权限发布该动作。它有独立、持久的 AID／IID 命名空间，与同名导入场景分开；现有配对身份不替换。

操作使用该桥实际配对的 HomeKit 控制器、公开密钥及逻辑灯范围，经同一运行时与持久准入执行，审计来源为 HAP。排队期间撤销配对、替换控制器密钥或退役旧桥会使未写出的工作取消。请求不能把离家动作与普通灯光／其他组的动作混在一个批次中；在产生任何输出前整批拒绝。

这是瞬时动作：写 `true` 表示请求执行，接受后回到 `false`；写 `false` 只复位，不是反向开灯，也不代表物理负载已经关闭。实际灯光、场景和 LED 仍由新鲜反馈更新。该动作可供家庭自动化调用，实际 iPhone／家庭中枢添加、调用及持续运行验收仍待进行。

## 2026-10-16 限定现场结果

2026-10-16 按用户逐步确认完成一次离家模块批量全关现场验证：同现网 ELF 的临时 Member 实例独立运行，12 模块各发一条原生全关，共 96 路（95 路照明／供电及明确批准的 0x01 第2路排气风机）。Root 从抓包独立按 TCP 字节序列重组，436 TX=424查询+12全关、无逐路回退／广播／电机命令；12 Written 对应96个精确不可变作用域，最后96路反馈均关，92个可见逻辑设备均 Confirmed OFF。用户确认四盏代表灯熄灭、其他灯与原已关风机保持关闭、窗帘停止；原 E2 rev14 已恢复，原配对／全部凭证／配置及程序不变，两个客户端无需刷新或重登自动恢复。首次辅助就绪检查误要求96个可见设备，未发控制即恢复；按96物理减4隐藏供电得到精确92可见集合并完成同ELF回环后才重开一次。临时令牌销毁、8446关闭。此结果不代表96路逐负载动作、原生App离家入口／HAP、活动场景接管或永久启用；现网Away仍未启用，长期稳定性及D/E、65/208/24范围保持。见[离家96路现场核查](evidence/stage-e-browser/away96-module-batch-field-root-check.json)。
