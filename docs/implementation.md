## A4 反馈事件投影

ObservedEvents 接收实际 HAP accessory handles 和 LightBinding，校验 AID、On／Brightness IID 与能力，再将 StateStore 的已确认反馈投影到 set_observed_value。只推送变化的特征值；desired、pending 结束、重复反馈及 stale 不生成虚假状态通知。断线清除去重缓存，恢复后相同有效值可重新通知；过期快照不推送。

投影器跟踪 boot ID 和严格连续的事件序号。首次使用、断档、重复／旧事件或发布被中断后必须显式 resynchronize；重新同步可重发当前有效状态。运行时须先发布对应读取快照，再调用投影。两个特征通知并非网络原子事务，重复通知和中途失败通过重同步收敛；尚未解决上游事件队列背压或加密会话发送保证。

## HAP 加密发送的短写修复

检查事件背压时发现上游 poll_outgoing 在 Pending／短写后丢弃尚未写完的明文，且加密写入没有保留未完成的密文记录。当前保留待发送明文及偏移，RecordWriter 缓存一个最多 1042 字节的记录，完整写出才确认对应最多 1024 字节明文。Pending 后续写同一密文，不再次加密或增加 nonce；零字节写入明确失败，加／解密计数器耗尽拒绝回绕。

## HAP 撤销后的通知授权

每次将特征事件放入连接发送队列前，重新读取持久化配对并验证控制器 ID。读取校验与入队保持同一共享存储锁；未认证、已撤销或读取失败时不入队，并触发该连接的传输终止信号。其他控制器的发送器独立。回归验证有效配对能收通知、删除后不能继续入队、该发送器终止而其他控制器仍可接收。

这覆盖下一次通知触发时的授权与终止，不等价于撤销时立即关闭空闲连接；已经入队的通知与删除请求响应的排空顺序仍需单独验证。直接在 ControllerUnpaired 回调中中断发起删除的连接会丢失其响应，尚未采用该做法。

## 持久化派发交接

## 在途派发期限

专属线程邮箱改用有界 std sync_channel，异步调用仍通过 oneshot 等待结果、try_send 背压。无在途任务时阻塞等待；有在途任务时只等待至该命令原始 deadline，每次取消息后也先检查期限，因此持续邮箱流量不能延后超时处理。

在途期限届满时尝试把 writing 转为 uncertain、结束仲裁写入并停止实例。持久化失败仍停止，原 writing 留给下次启动恢复；不声称失败的审计写入已经成功。迟到完成报告、同代际 synchronized 和新提交均拒绝。部分写入回报也停止实例，不能用旧代际重新就绪继续。无邮箱流量超时、迟到成功与拒绝重新准入已有集成回归。

这不能中断传输线程已经阻塞的系统调用；传输层仍须采用有界 I/O 和发送前 deadline/epoch 校验。现场连接及完整恢复所有者尚未接入。

## 传输所有者接线

TransportOwner 接收已经建立的有界、无缓冲 Connection 集合，不自行连接现场。票据携带配置网关 ID；step 从 Admission 取得持久化票据、移出对应连接，spawn_blocking 中使用同一单调时钟调用 send，随后等待 finish_write 的持久化结果。只有完整发送及审计均成功才放回连接并允许下一次 step。缺少网关连接、部分发送、工作线程失败、调用取消或审计失败均不重用该所有者；进程恢复仍不重放。

## 传输反馈读取入口

TransportOwner::receive 对指定网关执行一次有界读取，阻塞 I/O 位于工作线程。返回网关 ID、连接 transport epoch、Admission 同源单调接收时间及 Receive，保持原始帧直到配置解码，不把原始反馈提前视为状态确认。分包缓冲保留在同一 Connection；EOF 丢弃残帧并停止所有者，显式通知 Admission 停止新接受/派发及旧代际重新就绪。

Feedback 从已校验配置建立各网关 Registry 与已启用通道到 DeviceId 的索引，使用同一控制运行代际和有界 StateStore。apply 校验网关、外层/帧批次 epoch、非递减接收时间及最多 103 帧，再按型号解码。未知/非法反馈不更新设备；有效反馈只更新 observed，不修改 desired、pending 或命令日志。断线使当前运行全部确认状态过期并停止该投影实例，恢复须重建运行代际。

组件回归覆盖错误网关/代际、非法百分比、真实反馈状态、倒序时间及断线后旧反馈拒绝；测试及 Clippy 通过。当前尚需接入传输所有者和 HAP 快照发布，未形成在线闭环；未实现持久化反馈因果关联，不将碰巧匹配的目标认作执行 ACK。

## 传输到反馈快照组合

ObservedTransport 封装 TransportOwner 与 Feedback，读取后先完成配置化投影，再返回读取结果。未完成的分包不更新 observed；完整有效反馈才能确认。断线、传输错误、投影失败或调用取消使组合实例不可继续控制；snapshot 将仍然 Confirmed 的值呈现为 Stale，保留最后数值但不谎报在线。取消通过 await 前设置不可用、成功后清除来处理，无需在 Drop 中执行异步操作。

新增集成回归从实际分包流读取亮度反馈，验证 Unknown→Confirmed→EOF 后 Stale 以及拒绝后续派发；Admission/传输测试共 10 项及 Clippy 通过。该组合尚未发布 HAP 事件；错误/取消的快照质量覆盖不生成新事件游标，服务接线时必须同步健康状态或强制重同步，不能依赖旧游标推断没有变化。

## 失效质量事件修正

ObservedTransport 不再用普通快照覆盖代替状态变更。同步 Operation 守卫在错误返回或 future 取消时调用 Feedback::invalidate，将确认状态写为 Stale 并生成 Quality 事件；成功路径解除守卫，正常读取不产生临时离线事件。显式断线沿原 StateStore 断线路径生成事件。重复 invalidate 不重复发事件。

只有状态事件计数耗尽等投影失败才保留快照安全覆盖，同时 events_since 明确返回需重同步错误。新增失效幂等/单事件回归，并在传输 EOF 集成回归检查 Quality 事件；12 项接收/反馈测试与 Clippy 通过。未来 HAP 事件接线可以读取这些真实游标；取消守卫本身尚需专门并发取消回归，当前测试未覆盖其所有时序。

## 阻塞读取取消回归与停止传播

TransportOwner 操作守卫在取消或异常退出时同步设置 Admission 共享停止标志，不依赖邮箱剩余容量；专属线程在处理下一条消息前检查标志并停止准入。已在处理中的事务仍可能完成，仍遵守结果不确定/不重放边界。传输所有者继续不可复用，已启动的阻塞系统调用仍由其自身超时约束。
