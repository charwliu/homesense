## A4 反馈事件投影

ObservedEvents 接收实际 HAP accessory handles 和 LightBinding，校验 AID、On／Brightness IID 与能力，再将 StateStore 的已确认反馈投影到 set_observed_value。只推送变化的特征值；desired、pending 结束、重复反馈及 stale 不生成虚假状态通知。断线清除去重缓存，恢复后相同有效值可重新通知；过期快照不推送。

投影器跟踪 boot ID 和严格连续的事件序号。首次使用、断档、重复／旧事件或发布被中断后必须显式 resynchronize；重新同步可重发当前有效状态。运行时须先发布对应读取快照，再调用投影。两个特征通知并非网络原子事务，重复通知和中途失败通过重同步收敛；尚未解决上游事件队列背压或加密会话发送保证。

## HAP 加密发送的短写修复

检查事件背压时发现上游 poll_outgoing 在 Pending／短写后丢弃尚未写完的明文，且加密写入没有保留未完成的密文记录。当前保留待发送明文及偏移，RecordWriter 缓存一个最多 1042 字节的记录，完整写出才确认对应最多 1024 字节明文。Pending 后续写同一密文，不再次加密或增加 nonce；零字节写入明确失败，加／解密计数器耗尽拒绝回绕。

## HAP 撤销后的通知授权

每次将特征事件放入连接发送队列前，重新读取持久化配对并验证控制器 ID。读取校验与入队保持同一共享存储锁；未认证、已撤销或读取失败时不入队，并触发该连接的传输终止信号。其他控制器的发送器独立。回归验证有效配对能收通知、删除后不能继续入队、该发送器终止而其他控制器仍可接收。

这覆盖下一次通知触发时的授权与终止，不等价于撤销时立即关闭空闲连接；已经入队的通知与删除请求响应的排空顺序仍需单独验证。直接在 ControllerUnpaired 回调中中断发起删除的连接会丢失其响应，尚未采用该做法。

## 灯光场景结构化导入

导入报告新增 scenes：每个场景使用包含所属项目节点的稳定 ID，保留名称、禁用标记、白名单元数据、成员顺序、成员跟踪／flash／ignore_ramp 标记及各步骤 level、source_delay、source_rate。延迟和渐变字段仍是 Control4 原始整数，未擅自转换为 HomeSense 时间单位或执行动作；原文 SHA-256 用于回查。未识别字段只记录名称并保留未处理状态，未知值不扩散到报告；重复字段、非法亮度和负时间拒绝。

## 命令接受日志与启动恢复

homesense-storage schema 2 增加 command_journal，保留 boot ID／命令 ID、配置 revision、设备、来源、版本化意图编码、传输／控制代际、截止时间和状态。accept_commands 在一个 Immediate 事务内核对活动 revision 并接受最多 128 条命令；重复 ID、过期／越界或任意插入失败都回滚整批。该 API 不代替鉴权、能力检查、请求幂等或队列容量预留。

状态转换要求预期旧状态及单调时间，禁止 accepted 直接跳到 observed；重启时以新 boot ID 将旧 accepted／writing／written 记录标为 uncertain，保留终态，恢复接口只返回审计数量，不提供重放命令。版本 1 数据库自动迁移并保留配置记录。记录采用 4 字节版本化审计意图（不是总线帧），仍需运行时配合原配置解析审计详情。

新增 3 项回归覆盖事务故障、重复 ID 回滚、revision 冲突、非法转换／时钟、关闭重开后的恢复与旧 schema 迁移；存储 crate 共 10 项测试及 Clippy 通过。尚未接入队列预留提交屏障、HAP 接受、执行状态落盘或日志保留策略，因此在线持久化接受尚未完成。

## 队列发布与接受事务屏障

Arbiter::submit_batch_committed 在私有队列副本上验证准入、容量、合并和 STOP 取消；持有独占仲裁器借用调用提交函数，成功后才替换运行队列。准入失败不调用存储，提交失败不发布副本或消耗队列命令编号。原 submit_batch 复用该路径但仍为内存接受。

Store::accept_queue_batch 把新命令与旧／同批被替换命令的取消状态一次提交，schema 3 增加 cancellation_reason。取消更新必须匹配原 accepted 记录、revision、设备与意图，不允许悄悄漏掉取消审计。新增集成回归覆盖数据库插入失败保留旧队列、重试同编号、亮度合并、STOP 失败回滚和同批替换；core 与 storage 共 38 项测试通过，Clippy／格式检查通过。

提交函数同步运行，只适合专属运行时／阻塞存储任务，不能直接阻塞 HAP 网络回调。提交结果不确定时运行时必须进入恢复流程，不能据此自动重试；进程若在数据库提交后、内存队列发布前退出，启动恢复仍把记录置 uncertain 而不重放。在线异步接受、持久化状态推进及传输接线仍待实现。

## HAP 异步接受接口

WriteBatchHandler 新增 write_async，原同步适配器通过默认实现兼容；原生分组入口等待异步接受结果后再提交订阅变化。AsyncLightWriteHandler 先规范化完整请求，再等待运行时提交，保留失败状态；它的同步 write 入口明确拒绝，不能绕过持久化等待。适配器仍不得重入 HAP 配件／订阅锁，也不直接操作总线。

新增应用层测试覆盖真正 Pending 的接受等待、成功／背压返回、主体验证及非法请求不进入运行时；新增候选测试确认异步接受前不提前返回，拒绝后订阅不变，成功后订阅提交，配件缓存均不被意图提前更新。应用写入测试 3 项、候选 43+8 项以及 workspace Clippy／格式检查通过。

接口尚未接入专属存储／仲裁任务、请求时限和控制器撤销检查。调用方取消等待与持久化提交之间仍可能产生未知结果，不能据此自动重放命令；在线运行时需明确记录并处理这一边界。

## 有界异步准入任务

homesensed::admission::Admission 将 AsyncLightWriteHandler 接到专属线程：有界 Tokio mailbox、按提交时刻确定的请求 deadline、配置绑定与真实编码能力预检、运行时授权回调重查，以及队列／SQLite 接受事务屏障。只有事务成功后才返回接受结果；存储失败使该实例停止后续接受。Live 模式启动时网关未就绪，必须由连接所有者显式报告匹配的 epoch／revision 已同步；当前仅接受即时灯光命令。

启动时通过规范化数据库路径对应的 runtime.lock 独占锁防止第二个 Admission 所有者，读取并验证活动配置，并将旧 boot 非终态记录恢复为 uncertain。显式 shutdown 等待数据库与锁释放；它不派发或恢复旧命令。鉴权回调由可信会话所有者提供，须有界，尚未直接绑定 IdentityStore 的持久化权限撤销事务。

三项集成回归覆盖真实 AsyncLightWriteHandler → worker → durable accepted、重复所有者拒绝、授权改变后的拒绝、关闭／重开后的 uncertain、存储故障停止后续接受、邮箱满和排队超时。测试与 Clippy／格式检查通过。此任务尚无总线派发、状态推进或完整 HTTP 服务入口；等待取消与提交并发仍按结果不确定处理，不能自动重试。
