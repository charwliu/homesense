# 服务生命周期

数据库格式升级须按[完整状态回退流程](state-upgrade-rollback.md)准备一致快照；跨格式回退不能只切旧二进制。复制恢复须校验内容，避免同大小、同时间戳的 SQLite 文件被跳过。每次升级核对实际程序与数据库格式的兼容性。

`serve-automation-tcp` 的运行时长参数支持两种明确模式：

- `1..86400` 秒：保留限时运行接口，截止时间从初次完整反馈同步后开始计算。
- `forever`：没有整体截止时间，服务持续运行，直到显式停止或遇到不可恢复的内部／持久化错误。它不会换算成很大的秒数，不依赖定时重启续期。

示例参数结构：

```text
homesensed serve-automation-tcp DEVICES AUTOMATION STATE_DIR forever --coexistence-confirmed [原有 HAP／HTTPS 选项]
```

配置审核、共存确认、模块校验、访问权限与 HAP 身份规则保持原有要求。命令启动前会注册 SIGTERM 和 SIGINT；收到信号后请求正常退出，结束运行时、关闭监听与连接并释放持久状态的独占租约。

无整体截止不等于无操作边界：连接建立、反馈查询、命令接纳、写入、发布请求与安全 STOP 的既有超时继续有效。常驻启动尚未同步时，连接／查询失败持续退避重试，完整同步之前不启动规则和监听。已建立服务的通信故障期间保留管理服务与已配对身份，控制仍保持不可用；恢复轮次有界退避并轮换查询起点，所有注册输出必须在同一个新代次获得完整新鲜反馈，旧命令不会重放。

停止若发生在配置发布屏障之前，该请求不会进入新的发布屏障。已受理的发布先排空保留的安全 STOP 并完成原子持久提交，再响应停止；不会在退出过程中开启新配置的控制运行时或重放启动规则。发布收尾有独立的操作上限，超时或持久结果不确定时会明确要求检查当前版本，不能按失败提示自动重试设备动作。发布请求自身超时不等于配置回滚。

库调用者可以通过 `RunMode` 和 `RunControl` 明确选择有限／常驻模式，并通过 watch 停止通道结束服务。原有接受 `Duration` 的有限接口继续可用。通道关闭也视为停止请求。


生产服务由 systemd 管理，启动命令从服务单元读取，配置以持久活动版本为准。维护时按[部署指南](../deployment/nanopi/README.md)核对运行程序、主角色、配置和恢复守护，不用周期重启代替正常常驻。
