# 场景目录的合并入口

场景开关已经通过 `scene_switch_groups.members[].off_scene` 明确绑定开启和关闭配方。对于不需要独立展示的关闭配方，在对应 `scene_metadata` 项设置 `catalog_hidden: true`。目录只保留公开场景，由同一 ID 的开启／关闭操作选择原配方。

该标记默认为 `false`，不根据“关闭”“全关”或同名文字自动隐藏。内部配方仍保留在配置中，可供场景关闭、嵌套动作和实体面板执行；原有授权不会将它重新加入公开 HTTP 场景目录。隐藏本身不改变灯光命令、变量、LED 联动或设备权限。配置管理导出仍包含完整配方，编辑场景时应保留元数据中的此字段。

同一房间的“全开／全关”在日常目录中统一为“全部”。已有全开动作保留原控制范围；只有全关配方的房间需先补齐明确的开启配方及状态判定，不能只把关灯动作改名。实体面板上的全开／全关键仍保留各自原动作与名称。“离家”不作为房间全关合并。

“全部”卡片的点按在服务端读取实际灯光反馈：范围内任意灯亮则执行原全关范围；全灭才执行全开。未确认或缺失反馈不当作全部关闭。它使用独立的条件动作，不与原来的模式选择变量争用同一个选择值。墙面板“全开／全关”各自明确执行对应动作，不采用此卡片切换规则。

共享供电的灯需同时有供电和非零调光才算亮。`scene_tracking` 的 `powered_light` 谓词以 `device` 为供电、`dimmer` 为调光端，按两者实际反馈展示活动状态；只开继电器或仅保留非零调光都不算灯亮。状态投影和点按条件使用同一组供电／调光关系，不新增 App 轮询。

`scene_tracking.hap_activity` 默认 `true`，保持原配置兼容。若只需在 App 展示活动状态，显式设为 `false`，避免为 Apple「家庭」已选场景额外分配第二张只读活动卡片；原场景动作及配件身份保留。

原生 App 的“全部”卡片使用已确认的负载活动显示操作文字：`Active` 为“关闭”，`Inactive` 为“开启”；未知、待确认或没有只读活动配置时仍显示“执行”，不猜测方向。该显示不把 `activity` 变成明确的 `on` 请求；卡片和详情仍调用同一个场景，由服务端按最新反馈判断。普通只读活动场景保持原执行动作及文字。
