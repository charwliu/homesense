# 场景目录的合并入口

场景开关已经通过 `scene_switch_groups.members[].off_scene` 明确绑定开启和关闭配方。对于不需要独立展示的关闭配方，在对应 `scene_metadata` 项设置 `catalog_hidden: true`。目录只保留公开场景，由同一 ID 的开启／关闭操作选择原配方。

该标记默认为 `false`，不根据“关闭”“全关”或同名文字自动隐藏。内部配方仍保留在配置中，可供场景关闭、嵌套动作和实体面板执行；原有授权不会将它重新加入公开 HTTP 场景目录。隐藏本身不改变灯光命令、变量、LED 联动或设备权限。配置管理导出仍包含完整配方，编辑场景时应保留元数据中的此字段。

同一房间的“全开／全关”在日常目录中统一为“全部”。已有全开动作保留原控制范围；只有全关配方的房间需先补齐明确的开启配方及状态判定，不能只把关灯动作改名。实体面板上的全开／全关键保留各自名称。“离家”不作为房间全关合并。

“全部”卡片的点按在服务端读取实际灯光反馈：范围内任意灯亮则执行原全关范围；全灭才执行全开。未确认或缺失反馈不当作全部关闭。它使用独立的条件动作，不与原来的模式选择变量争用同一个选择值。

rev46 起，1 层休闲区 F1 卧室门口 4 键、F1 楼梯口 5 键，以及四间卧室的 1 键“全开”使用实体键专属的切换条件：本键覆盖的灯未全部达到全开值时执行全开；全部达到全开值后再次按下，执行该房间全关。反馈未知时不猜测方向，也不发送灯光命令。四间卧室的 5 键“全关”仍固定执行关闭。休闲区两颗“全开”的现网配方含主灯、筒灯、灯带和走廊灯；“会客”仍保持灯带关闭。**待修正：**灯带 1／2 是共用 `control4:99` 供电的组合逻辑灯（`control4:354`／`control4:356`）。rev46 场景直接写物理供电和调光通道，尚未调用组合灯的反馈及联合规划入口；不能把八路物理写入称作八盏逻辑灯，也不能仅删除供电命令。完成逻辑灯场景入口及离线验收后再发布修正。其余实体“全开／全关”键维持原有明确动作。

2026-10-21 在 nanopi 的独立目录部署 ARM64 Release 二进制并于仅启用 lo 的网络命名空间完成部分验证：rev46 配置校验和 3 秒自动化模拟通过，组合灯专项 22 项通过、0 失败；Mac 与 nanopi 的 ELF SHA256 相同。该轮只验证现有组合灯控制与隔离运行，未实现或验证“场景通过组合逻辑灯开启灯带”，没有接入真实 485 网关，也未切换现网服务。原始记录保存在忽略的 `deployment/ngr/private/nanopi-half-test/`。

共享供电的灯需同时有供电和非零调光才算亮。`scene_tracking` 的 `powered_light` 谓词以 `device` 为供电、`dimmer` 为调光端，按两者实际反馈展示活动状态；只开继电器或仅保留非零调光都不算灯亮。状态投影和点按条件使用同一组供电／调光关系，不新增 App 轮询。

`scene_tracking.hap_activity` 默认 `true`，保持原配置兼容。若只需在 App 展示活动状态，显式设为 `false`，避免为 Apple「家庭」已选场景额外分配第二张只读活动卡片；原场景动作及配件身份保留。

原生 App 的“全部”卡片使用已确认的负载活动显示操作文字：`Active` 为“关闭”，`Inactive` 为“开启”；未知、待确认或没有只读活动配置时仍显示“执行”，不猜测方向。该显示不把 `activity` 变成明确的 `on` 请求；卡片和详情仍调用同一个场景，由服务端按最新反馈判断。普通只读活动场景保持原执行动作及文字。
