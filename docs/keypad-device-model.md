# Keypad 设备与子功能

每块 TS6-86 对应一个稳定 Keypad 对象，按键、LED、背光和工作模式是其子功能。父对象组织能力、业务引用与逐键权限，不作为整板电源开关。

一个 Keypad 具有稳定逻辑 ID、名称、房间及 `module_id`。物理网关和 RS485 地址仍由模块映射解析；移动房间或更换模块地址不改变 Keypad ID。模块对象继续承载物理观测，Keypad 组织该面板的能力及业务引用，两者不分别维护相互矛盾的物理状态。

六个按键是编号为 1–6 的子功能，包含按下／释放事件及各自 LED 控制。背光、按键声音、反馈／工作模式和诊断信息按型号的已验证能力提供。工作模式须使用明确的枚举含义，不能与 LED 颜色或按键事件混为一谈。没有已验证协议的属性显示不支持或未知，不推断读回格式。

原生按键接口使用一块面板一个父对象，六键按1／2、3／4、5／6排列。每键具有配置用途、事件、LED来源和可用性；颜色提示与实际观测分开。配置管理编辑面板和按键用途，日常家庭页面通过 HomeKit 配件控制，界面显示范围见[App 指南](../apps/HomeSense/README.md)。


命令目标、已写出记录和真实反馈分别保存。按键按下不能证明 LED 已变红，TCP 写出也不能证明背光或工作模式已改变。没有可用读回时，界面可以展示“最后写出”并保留未知实际状态；断连、过期和重启不能把旧值冒充当前确认值。

设备控制须走既有权限、准入、队列、持久审计和唯一传输所有者。面板级设置按明确权限检查；仅获授权某一键 LED 的凭证，不能因此控制其他键、背光或整个面板。模式切换可能影响 LED 联动，不能在打开详情、切换 App 模式、迁移或启动时自动发送模式设置命令。

迁移须保留旧逐键 ID 的解析兼容性，并把它们明确映射到 Keypad 的子端点。原规则、窗帘 LED、场景指示灯链接和审计来源继续引用原有子端点，不能因合并设备而丢失。旧凭证范围不能扩大；已有 Apple 家庭附件身份和配对保持稳定，HomeSense 内部设备归并不自动删除或重建 HAP 附件。新增父设备的授权和 HAP 展示策略须在实现中明确记录。

配置迁移先离线生成可预览草稿，核对所有旧引用与权限后再发布。重复父设备、重复键号、跨模块子端点及未知模块引用必须拒绝；旧配置继续可读取，缺失的子功能状态保留未知。发布按已审核的执行归属启用，不能因数据结构转换自动获得控制权。

验收覆盖一个模块只对应一个面板、逻辑 ID 在改址后稳定、旧规则与 LED 链接保真、逐键权限不扩大、状态来源区分、断连与重启、服务端推送、原生 App 一面板一入口及完整管理编辑。软件结果与实际 LED／背光／工作模式读回的现场验证分别记录。
