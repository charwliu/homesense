# 统一按键入口

统一按键 API 与查询调度增量已发布，全屋 28 块面板、168 键的实体执行配置已启用，现场验收进行中；未显式配置的实体接管默认关闭。原 Control4 工程与 EA-5 供电保持不变。同一动作的执行归属需要由安装者保证；配置中的隔离声明不能当作实际隔离测量。

`POST /api/v1/keypad-actions` 接受一个已认证虚拟按键动作：

```json
{"revision":"1","keypad":"panel","key":1,"request_id":"unique-request-id","gesture":"activate"}
```

只接受这些字段和 `activate` 手势。客户端不能指定场景、目标设备、LED 颜色或声称来自实体事件。服务端解析同版本的启用键映射，检查来源端点以及场景全部所需分支／负载权限，再复用场景、原生相对动作、窗帘或离家执行链。普通房间场景和 HAP 不猜测物理来源键。

版本通过 `/api/v1/session` 的 `capabilities.keypad_actions` 公告：`version:1`、`path`、`gestures:["activate"]` 和 `indication_schema:1`。目录与 WSS 的每个键另含可空的 `activation`，给出同版本面板、键号和 `available`；旧 `action`／`card_action` 为兼容保留。

## 回执与幂等

新动作使用 202 回执，包含 `request_id/outcome/boot/revision/keypad/key/gesture/retry:false`、`execution` 与 `indication`。`execution.kind` 是 `scene`、`motor` 或 `away`，命令和运行编号只表示受理或写入记录。响应丢失或执行结果不确定返回 `outcome:unknown`，不自动重试。

幂等范围是稳定凭据 ID、端点与请求编号；不同凭据即使共用控制器也不共用回执，凭据的进程内代次不进入该持久标识。指纹绑定版本、面板、键、手势与服务器核实的当前权限；同一凭据权限变更后，原编号冲突返回 409，不披露旧回执或重新执行。同版本重复请求返回 200 和原保存结果，不重复执行；编号对应不同指纹返回 409。版本不匹配在查收据前返回 409，旧版本回执不会恢复提示。跨进程旧收据仍可能带旧 boot，客户端必须丢弃其中提示。

格式或手势错误返回 400，权限不足返回 403，版本冲突返回 409，禁用／缺失映射返回 422，受理前服务或存储不可用返回 503。成功解析请求后，拒绝响应保留请求编号；认证或格式检查前的错误可以没有编号。受理后不确定结果不能改写成确定拒绝或成功。

## 提示与真实状态

`indication` 单独携带请求编号、端点、`operation_sequence`、`event_sequence`、来源、状态、可空颜色及恒为 false 的 `observed`。它是软件提示；原 `led.observed` 继续为 null，`led.last_written` 继续表示历史写出，不能当成模块颜色读回。

HTTP 点击的来源为 `authenticated_click`，`event_sequence` 为空。服务端核验的原始按键执行来源为 `button_event`，`event_sequence` 为本代次原始事件 cursor 的正整数十进制字符串，请求编号为 `wall-{boot UUID 的32位小写十六进制}-{event_sequence}`。它只用于诊断事件来源，不能与操作序号或较新的 `key_event.version` 比较大小来排序提示，也不允许客户端伪造来源。

来源键只允许在本次动作成功评估与受理后的短窗口内，发送一次实际评估出的自身 LED 值。同一因果阶段、同一网关的灯光控制与本键提示合成一次有界物理写出；仍保留本键原截止。查询、未知 Toggle 或电机／STOP 等因果屏障不跨越合批。其他键和联动面板继续等待对应判据所需的完整真实反馈，保持总预算及首次反馈后的发送截止。已知相反点击会使旧来源提示失效；失败或被拒绝的点击不撤销上次有效来源。

已启用物理重核且开关组合无歧义的场景组，组合灯的 LED 可在本批次相关供电继电器全部实际反馈到目标后发送，不等待渐变亮度；亮度仍独立等六秒后读回。相同开关组合需要亮度区分的场景、未审核的 LED 映射及无供电继电器的调光灯继续要求亮度反馈。等待期间按需补查本次证明所依赖的物理端口，避免先到的继电器反馈在渐变结束前过期；不复用旧反馈、不放宽五秒新鲜度、不延长十五秒总预算，也不重新触发灯光控制。

没有自身 LED 命令的场景键，可以显式配置：

```json
"local_indicator": {
  "kind":"scene_selection","group":"reviewed-group","value":1,
  "selected_color":"red","unselected_color":"green",
  "review_evidence":"reviewed source On/Off command references"
}
```

配置必须精确对应本键的 `scene_toggle` 和同版本场景组成员；变量由组定义解析，不从名称猜测。已知分支按评估结果补自身 LED；物理推断场景选择未知时，只为当前已受理的按键补开启色提示，最终选择仍等待逐灯实际反馈。提示不能初始化场景状态。普通场景、HAP 及其他面板不会获得这个例外。未补齐的来源映射以 `mapping_gap` 报出。

窗帘按最终解析的运动命令确定本键提示。同向再次点击若实际成为 STOP，方向键提示保持红，独立停止键为绿；STOP 始终在提示前写出，提示失败或过期不能阻止已经有效的停止。该临时提示随后可被成功写出的标准窗帘模型提示覆盖并退休，中停时两个方向键红、独立停止键绿；它不永久固定方向键颜色。现有估计行程和硬件参数保持。

离家动作的来源键提示不依赖关灯反馈，同网关时跟随模块全关命令在同一有界批次内写出；不为抢先提示而延后全关。没有本键来源的兼容完成提示仍等全部关闭反馈，整体成功不会提前取消这一合法的后续 LED。其他关联 LED 仍等待有效关闭反馈，不获得来源键例外。

有界离家重试只保留最初的一条兼容完成提示，其等待截止绑定原逻辑操作；本次操作自己提交的重试只替换受影响模块的命令编号、实际写出围栏和版本。不同操作不能借用该提示，已取消或已打开的发送窗口不重新激活；首次完整关闭证明后仍最多两秒发送，且受原操作截止限制。完成等待的补读只维护观测新鲜度，收到新鲜“仍开启”反馈后交给模块重试，不反复抢查同一路；实际开启或未知仍不能释放完成 LED。

这类离家完成提示逐个核对原始输出：组合灯供电继电器关闭时，其 AD8 仍须读回零；补读不能用供电继电器代替该 AD8 通道。普通组合灯／场景的关灯反馈语义不受此规则改变。

## 推送顺序与退休

状态可能是 `pending`、`written`、`mapping_gap`、`unknown`、`superseded`、`cancelled` 或 `retired`。被覆盖、取消或退休的提示颜色为空。后续成功写出的 LED 命令若覆盖旧提示，旧提示变为 `retired`，并保留同一操作序号作为退休标记；单纯 Accepted、失败和不确定写出不算成功覆盖。退休只改变显示，不撤销有效的执行或 STOP 权限。

六键状态按可见端点分别保留 LED、背光、声音及工作模式的最新请求和最后成功写入。该投影不受其他按键的最近命令数量影响；查询已发送、Accepted、失败或不确定结果不会替代最后成功设置。颜色仍为 `last_written`，不伪造 `observed`；重启、配置版本和传输代次仍按原来源标识区分，未授权子功能不因同面板其他键可见而开放。

后台 LED 扫描在真实反馈、待确认目标或相关场景选择改变后，优先重算受影响按键，包括已访问的按键。物理场景按整组灯光及供电依赖检查。每批最多提前八个目标，其余目标从原游标继续轮转；保留十六个目标的批次上限、查询机会及原硬截止，持续变化不能延长截止或重放未完成的写入。

相对场景完成最终查询后，其待确认标记和物理选择同样会使 LED 扫描缓存失效；不要求再改变一次灯光或记录变量。缓存不包含同值回包的时间戳，重复反馈不会反复制造变色。LED 同步只将调光设备的目标作为亮度等待，继电器的内部策略记录保留，但不阻塞已得到真实继电器反馈的 LED；调光设备原有的恢复亮度保护继续生效。

WSS 比较完整键盘投影，LED 生命周期变化不依赖物理 cursor 增长，也不伪造物理事件。客户端按同一 boot／版本和每键操作序号排序；退休标记优先于同序号的旧 HTTP 提示。HTTP 先于或晚于 WSS 都不能恢复旧色。断连、失效、配置和传输代次改变时清除提示缓存。

原始 `key_event` 带稳定语义版本、时间和按下状态，不是颜色观测，也不是每帧翻转请求。实体事件执行将复用同一手势和长按释放所有者；默认保持关闭，不能把观察模式的结果作为接管完成。

## 原始按键的执行归属

只有明确声明 `event_control.owner=homesense`、完成旧写入路径隔离审核且六个键均映射并启用的手动反馈面板，才能执行原始按键。`legacy_writer_isolated` 是操作者声明，运行状态不会把它冒充为已测得的硬件隔离证据。

每个运行代次只允许一个有效的原始按键执行者。退休后可重新注册，重新订阅从当前 cursor 开始；连接时已按住的键须先释放，不重放历史快照。普通短按和长按都只在一次有效释放上执行；重复按下、重复释放、LED 写入回显与超长按取消不产生第二次动作。同一端点不得同时启用旧面板规则、场景观察执行或长按调光。

原始事件分发与控制请求都分别为 STOP、可能解析为同向 STOP 的窗帘键及普通操作保留有界容量。普通队列溢出只消费并丢弃溢出事件，不退出执行者，也不挤掉已有 STOP；墙键和 HTTP 的同级请求公平处理。失效事件不重放，STOP 自身的持续过载仍受其独立容量限制。

## 实体按键与周期查询协调

收到当前连接代次、已登记 TS6 的有效按下或释放报文后，仅将该总线的新周期查询（包括普通保鲜查询）延后 300 秒；后续有效按键重新计时。其他独立总线继续运行，主动反馈照常更新真实状态。等待期间不改观测时间，不延长状态有效期，不补造释放事件。

按下后另保留最多 2 秒的释放接收窗口，真实释放立即结束此窗口；重复按下不延长窗口。已写出的灯光动作所需的反馈确认查询不等待 300 秒。AD8 中间亮度在成功写出渐变命令 6 秒后才发首次确认查询，且仍要等释放窗口和已有查询占用结束；整模块查询包含渐变中的通道时同样等待。0%／100% 直接开关不加这段延时，同一路后续直接写入清除旧渐变等待。主动反馈一直接收，首次读回若仍未落定，仅在原有反馈预算内继续确认；不延长 LED 总截止。已发查询保留原始应答期限和故障处理；断连、配置／连接代次改变清除旧窗口。按键接收保护和周期延后本身不阻止 STOP 或普通控制；若已有查询正在等待应答，仍须遵守下节的总线占用限制。

## 查询应答期间的总线占用

初始化、周期／写后确认及管理员手动输出查询共用发送互斥规则：同一总线上的查询未收齐有效应答或到期之前，不发送下一条查询或控制。AD8 整模块等待全部八路；逐路查询等待对应一路，重复、错误地址、错误代次或非法值不能补齐其他通道。不同独立总线仍可推进。

管理员查询每次完整写出后使用最多 500 毫秒的应答窗口，不合批发送多条查询。普通控制和 STOP 均等待当前应答窗口释放，STOP 在后续可用发送机会保留优先级；等待不会延长任何已受理控制的原始截止。手动查询超时不补反馈、不自动重放，也不把发送记录改成已观察成功；查询回复不视作主动反馈而触发新轮询。

收齐应答后还保留配置规定的发送／换向间隔；重复回包不能无限延长，等待上限仍锚定原应答截止及一段换向间隔。协议没有事务编号，匹配应答集仅用于管理发送占用，不升级为严格的命令因果证明。

### 记录模式未知时的首次点按

`scene_toggle` 已启用物理反馈推断时，选择未知仍交给逐灯相对规划。没有该策略的记录模式，首次点按则明确执行已审核的开启分支；不以 App 颜色或缺失观测初始化状态，成功执行后才建立选择，之后再次点按可以关闭。包括未知值在内的选择版本会一直核对到入队，并发选择变化会拒绝旧决定。只有经过授权的当前按键可以使用其审核过的即时提示。

逐灯相对规划中的 AD8 中间亮度同样使用原生渐变指令，并在该控制阶段全部成功写出后至少等待六秒再发送最终查询。仅含直接开关或 Toggle 的配方保留原五秒完成期限；需要 AD8 渐变的配方使用十五秒总期限，后续阶段不续期。其串行查询队列只使用本次操作剩余的完成预算，避免多路最终查询共用普通控制的两秒排队期限；灯光写入期限和单次查询应答窗口保持。即时提示插入后仍按实际灯光命令编号记录 Toggle，不能把 LED 写出当成灯光翻转回执。

场景投影改变时，扫描的八个优先位置先留给当前成功写入颜色需要改变的关联键；扫描刚好结束时也会在下一轮应用这个排序。投影和写入记录仅用于排序，不作为硬件LED反馈，也不取代实际写入前的反馈／权限检查。普通目标继续轮转，原始截止与批次上限保持。

启用物理推断的场景LED通过独立的新鲜选择、写后反馈和输出围栏证明后，可按当前实际状态更新，不被恢复亮度记忆的旧目标延后。原生操作仍待确认或场景仍活动时不放行；恢复目标本身及未启用该物理证明的旧链接保护均保留。

## 原生 App 的即时显示候选

App 点按立即显示目标色或执行中状态，房间场景卡片同样显示待确认层；服务端收到并评估实体按键后，通过现有 WSS 推送来源提示。后续受理结果可修正本地预提示，失败、取消、断开及固定到期撤回；不修改真实 `selected`、负载读回或 `led.observed`，不触发客户端轮询或自动重发。新版客户端尚未覆盖安装。
