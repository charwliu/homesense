# 场景选择观察模式

用户已确认：依据已核实的面板按键推断外部场景选择，明确标记推断，不发送灯光命令；初始选择未知时不猜测同键切换结果。EA-5 仍执行原程序，配置和控制范围不变。

## 已实现的状态机

`homesense-core::scene_observer` 只输出 `Inference`，不包含 Command、传输或规则动作。已知无选择／其他成员时按键推断选中该成员，已知当前成员时推断取消；未知保持未知，不当作 0。每个结果保留原始按键、事件序号、观测时间、完整代次与流代次，以及变量预期版本供事务 CAS 使用。

持续按住和重复报文不再次切换，短松开不丢失；按下间隔受去抖约束。过期或未来报文被消耗而不产生结果，不能在后续时刻重放。重启、传输／配置／控制代次变化或事件缓冲缺口后，旧推断来源不能作为新一轮已知选择；已有本地选择记录仍属于本地意图，不能声明为 EA-5 状态。

这里的“推断”不证明 EA-5 已执行分支、灯光达到目标或实际 LED 状态。不能依据某组亮度匹配来补造场景选中。

## 已实现的来源存储

schema 22 的 `scene_observation` 不可变审计记录与整数选择更新在同一 SQLite CAS 事务中提交，绑定实际变量版本。证据包括按键、序号、观测时间、互斥组、推断依据、boot 和所有代次；未知初始选择也保留 inferred 证据。重复／倒序事件和版本竞争被拒绝，不创建命令、场景或规则接受记录。

`scene_selection` 在一致读事务中返回数值和来源：只有当前完整 scope 匹配才返回推断值，否则值为未知、原证据仍保留。后续本地变量更新递增版本，旧来源不会跟随人工选择。普通 `logical_variable` 接口一律遮蔽当前版本的推断值；配置发布同样先转换为未知，不仅复制数字丢失来源。

存储入口属于进程内可信边界，尚未验证现场按键所有权／新鲜度，这些必须由后续 Admission 接线完成；不能直接开放为 Web 写入接口。本轮在干净源码快照通过 53 项存储测试（含 7 项新增）与全部目标严格 Clippy。实际运行 schema 21 的旧二进制创建升级前备份，新版迁移并通过 schema 22 备份检查；旧版拒绝升级后的库且文件不变，再用升级前备份恢复原记录。回退要求恢复升级前备份，不能降写 `user_version`。

现场数据库、身份和 release 均未更改。证据见 [存储及回退检查](evidence/stage-d-study/scene-observation-storage-check.json)。

## 后续接线契约（尚未实现）

1. 显式配置审核过的按键→互斥组成员映射，默认禁用。核查成员、设备类型和来源；拒绝与启用的 Rust 面板／长按输出归属重叠，以及观察变量触发的自动规则，避免把观察变成间接执行。
2. 运行时从同步后当前事件游标开始，仅接收当代新鲜按键。断链、配置切换或缓冲缺口开启新流代次；旧事件不补发。只读接口暂忙可延期，提交不确定时不重放按键。
3. 在授权 Admission 内，以实际变量版本 CAS 原子保存选择与来源证据。来源固定为 inferred，未知也记录为未知；竞争失败不覆盖更新的人工选择。推断来源需绑定当前变量版本，后续本地动作不能沿用旧来源。
4. 重启或发布时不把旧推断提升为本地确认值。普通自动规则不能把推断变量当作已确认输入；迁移须保留未知，不能仅复制数值而遗失来源。
5. HAP／Web 的选择与手动开关规划使用同一经过代次校验的选择快照。Web/API 和审计明确给出 inferred 来源及时间；Apple 家庭的 Bool 本身不携带来源，不能宣称其界面能显示置信度。必要的呈现及实际客户端行为需另行验收。
6. 已有新鲜熄灯证据继续取消选择与关联 LED。观察按键本身不发送灯光、窗帘或 LED 指令，也不重放 EA-5 的场景序列；由独立熄灯联动执行的指示灯清除保持原策略。

当前已完成状态机和来源存储，配置、运行时事件及用户入口接线仍未完成，因此没有可启用的现场观察模式。现有书房候选和 Linux release 不包含该功能；所有真实配置和联调资料继续保留本地。后续仍须核对当前集成版后再准备现场候选，不把存储回归当成按键接线或现场通过。
