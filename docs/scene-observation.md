# 场景选择观察模式

用户已确认：依据已核实的面板按键推断外部场景选择，明确标记推断，不发送灯光命令；初始选择未知时不猜测同键切换结果。EA-5 仍执行原程序，配置和控制范围不变。

## 已实现的状态机

`homesense-core::scene_observer` 只输出 `Inference`，不包含 Command、传输或规则动作。已知无选择／其他成员时按键推断选中该成员，已知当前成员时推断取消；未知保持未知，不当作 0。每个结果保留原始按键、事件序号、观测时间、完整代次与流代次，以及变量预期版本供事务 CAS 使用。

持续按住和重复报文不再次切换，短松开不丢失；按下间隔受去抖约束。过期或未来报文被消耗而不产生结果，不能在后续时刻重放。重启、传输／配置／控制代次变化或事件缓冲缺口后，旧推断来源不能作为新一轮已知选择；已有本地选择记录仍属于本地意图，不能声明为 EA-5 状态。

这里的“推断”不证明 EA-5 已执行分支、灯光达到目标或实际 LED 状态。不能依据某组亮度匹配来补造场景选中。

## 已实现的来源存储

schema 22 的 `scene_observation` 不可变审计记录与整数选择更新在同一 SQLite CAS 事务中提交，绑定实际变量版本。证据包括按键、序号、观测时间、互斥组、推断依据、boot 和所有代次；未知初始选择也保留 inferred 证据。重复／倒序事件和版本竞争被拒绝，不创建命令、场景或规则接受记录。

`scene_selection` 在一致读事务中返回数值和来源：只有当前完整 scope 匹配才返回推断值，否则值为未知、原证据仍保留。后续本地变量更新递增版本，旧来源不会跟随人工选择。普通 `logical_variable` 接口一律遮蔽当前版本的推断值；配置发布同样先转换为未知，不仅复制数字丢失来源。

存储入口属于进程内可信边界；现在由 Admission 验证实际反馈事件、授权、当前代次和变量 CAS，不开放为 Web 直接写入接口。schema 21→22 的旧二进制备份恢复已在此前检查点验证；回退仍须恢复升级前备份，不能降写 `user_version`。

现场数据库、身份和 release 均未更改。证据见 [存储及回退检查](evidence/stage-d-study/scene-observation-storage-check.json)。

## 已完成运行时接线

1. `scene_observation` 显式配置已审核的按键→互斥组成员及审核证据，默认禁用。启用时核验成员、面板类型与容量，拒绝与启用的 Rust 面板／长按动作重叠；普通自动规则不能触发或读取被观察的选择变量，包括展开后的场景条件。显式字面量写入仍属于本地意图。
2. Consumer 从当前反馈游标起步，只消费可信、已确认的按键事件。初始已确认按住的键先等待释放；按键状态未知不等于按住，第一条新鲜按下仍可处理。选择未知时保持未知。观测时间是主机接收时间，不证明远端发射时间或 EA-5 执行时刻。
3. Admission 所有者串行核验反馈租约、授权、配置／传输／控制／流代次，再以实际变量版本提交选择和不可变 inferred 证据。新本地变量更新会隔离先前已接收的旧按键，竞争失败不重新套用旧事件覆盖人工选择。
4. 断档、重连、重启或发布使旧推断失效；流失效标记不依赖队列剩余容量。事件被消费后不因等待取消或结果不确定而重放。普通变量读取继续遮蔽推断值，普通规则不能将其作为已确认输入。
5. HAP 与手动场景规划使用当前作用域的选择快照。Web 显示本地意图／按键推断／推断已失效／未知来源；HAP On 布尔值无法携带置信来源，不能声称家庭 App 展示推断标签。显式人工动作接受后建立新的本地意图，与旧按键证据分离。
6. 观察路径不构造灯光、窗帘、LED 指令，也不重放 EA-5 场景。初始未知不根据亮度匹配补造场景选择；未知和实际 LED 状态继续分别处理。

## 验证与剩余项

本次新增 8 项运行时联合回归及 1 项初始按住核心回归。限定源码的独立快照完整工作区 634 项通过、0 失败、0 忽略，全部目标严格 Clippy 与 14 项前端检查通过；首次完整运行的多桥恢复等待超时及随后重跑结果均保留在[证据](evidence/stage-d-study/scene-observation-runtime-check.json)中。

独立熄灯／LED 同步的来源丢失已修复。专用可信入口读取当前作用域选择；未改变的变量只在 LED 命令事务内校验版本，既不写回未知，也不提升为本地确认。应亮的一路关闭时，匹配的选中项清零；清理其他成员的 LED 保留当前推断值、版本和来源。接受前再次核验当前来源及事件流有效性，变量竞争或来源失效整批拒绝，不产生 LED 收据。

对当前推断值，按键前或同毫秒的灯光样本在规划时视为未知；同毫秒无法证明先后，等待新样本。其他负载未知不否决另一路独立的新鲜 Off。若 Off 来自 Dimmer 持久设定而非供电继电器读回关闭，还要求同一 boot 中按键之后完整写出的当前 0% 设定。旧 boot／旧零值不能靠新查询刷新成新关闭证据；仍遵守开关读回和 Dimmer 持久设定优先级。旧 Dimmer 零值只失去作为关闭依据的资格，不否决另一开关的独立新鲜 Off。所有已读取反馈仍受租约及未决输出检查保护，不承诺固定延迟。

旧推断规划在流失效后准入的并发边界另待核查；当前生产循环串行处理 Consumer 和控制 Receiver，孤立准入探针尚不能证明现场竞争，不能据此宣称生产故障。

因此当前实现仍默认禁用，未部署或启动现场服务；现有 Linux release 不包含此功能。家庭配置、按键绑定和联调资料只保留本地。当前集成版现场验证继续待办，D/E 尚未完成，EA-5 配置和控制范围不变。
