# 管理控制的精确来源授权

管理请求绑定发起凭据及其代次，不能由同一 controller 的另一凭据替代。授权在受理、排队、派发和实际写入边界重新校验。

## 授权契约

普通设备开关／调光／组合灯／已校准电机、模块单路控制与查询、手动场景／相对场景和运行取消，保留该次请求的精确凭据 generation；Cookie 还绑定精确会话及有效期。来源在异步模块绑定／查询预检前捕获，后续不会通过重新查找令牌而借用替换 generation。内部证明绑定 controller、配置 revision 和原逻辑操作内容，客户端不能提交、序列化或更换这份证明。

一次凭据配置更新总会更换 generation，旧请求及其未完成后效均取消，即使新 grant 仍允许同一目标。这是保守的在途取消政策；不表示降为 member 后仍在范围内的**新请求**失去普通控制权。单独撤销一个来源不会撤销同 controller 下另一份凭据。Cookie 登出仅使该会话的旧工作失效。

证明随接纳队列、时间线、嵌套即时场景、变量／场景结果级联、软件渐变、原生场景后续阶段和审核的窗帘提示 LED 后效传递。内部物理展开保留原逻辑授权：组合灯不要求额外授权隐藏供电端点；合法的 scene-only grant 不要求逐个列出场景内设备或审核的嵌套动作。它不会扩大来源可主动提交的其他逻辑操作范围。可信本地生产者、HAP 与其原有授权契约独立，不借此自动获得新的 Web 来源。

接纳队列与变量提交、原生切换阶段账本及选择完成投影，在源凭据／会话读锁内完成。派发再次检查，唯一传输 owner 在实际同步写期间也持有该来源读锁。已完成撤权后，尚未开始的写入必须为零字节；已经进入有界同步写的动作可以先于撤权完成，不承诺收回已经写出的字节。

尚未派发的已撤权命令取消，其时间线、渐变与派生会话停止未来动作，并保留已写出部分与取消审计。清理只撤销工作、释放预算和记录既有结果，不用管理员身份补发动作。若撤权发生在取得 Writing 票据以后、实际同步写以前，保留既有保守失败／恢复流程：零字节拒绝，结果不伪报 Written；传输 owner 显式恢复后，合法新来源才继续。不会自动重试被拒绝动作。

## 配置发布与安全 STOP

HTTP 发布证明绑定精确凭据、会话、预期版本及文档摘要；队列预检与进入屏障的同步临界区均重查权限。失效来源不能进入屏障或提交配置。

成功进入屏障是授权转移点：当时保留的有限安全 STOP 归属于已获授权的发布操作，携带不可序列化、不可克隆的一次写出票据凭证。凭证严格绑定原 STOP 的命令、目标、ID、来源类别、run_id、配置／传输代次、原截止时间及屏障的新 control 代次；只有这些已经保留的 STOP 可以继续。原一般来源租约不再阻断这份已接纳的安全清理，其他旧动作仍取消，所有新控制仍被屏障阻挡。不能更换目标、改为开／关等动作、延长时限、跨配置重用，也不能在屏障前借此绕过撤权。发布不会凭空生成此前未排队的电机 STOP。

受信任本地发布入口、HAP 和管理 API 分别遵守自己的来源契约。丢失响应或持久结果未知不允许自动重放控制。

## 部分写出

组合灯和场景展开保留原逻辑权限，隐藏供电不要求另授绕过权限。已经写出的帧不可撤销；未发后缀和延迟后效继续检查原来源。派发前撤权必须零字节拒绝，失败不能伪报 Written。

配置发布、取消、重连与来源失效均保留精确审计。验证使用本机合成身份、内存线路与数据库，不复制现场凭证。
