# 阶段 E 验收跟踪

目标依据 design.md 第 20、23–25 节：完成原生 Rust HAP 配件公开、场景入口、Web 管理和鉴权，验证配对、反馈、Siri、断线恢复与权限。阶段 D 的未完成项继续保留在 stage-d-progress.md，不能因目标扩展而视为完成。

| 范围 | 已有基础 | 完成所需证据 |
| --- | --- | --- |
| HAP 灯光与身份 | 原生桥、稳定 AID/IID、配对存储、灯光反馈与限定现场验证 | 当前集成版本的配对、重启、事件、断线恢复与权限回归 |
| 场景动作入口 | 场景和规则运行时、取消、持久运行与命令记录正在整合 | 选定场景瞬时 Switch；接受后复位，关闭不反向执行；失败可追溯 |
| 窗帘动作入口 | 开／关／停控制及书房限定测试 | 每路三个动作开关；无虚构位置；iPhone／Siri／现场停止验收 |
| Web 管理 | 配置、命令及场景后端组件 | 鉴权界面、设备与运行状态、控制与取消、错误呈现和权限测试 |
| 可选面板公开 | 内部手势和事件路由 | 显式选定按键、无重复触发；LED 和内部变量默认不公开 |
| 隔离与安全 | 单写入仲裁、持久准入、代际屏障 | HAP／Web 共用权限和控制入口；异常输入、请求限额及通道失败隔离验证 |

工作方式：按依赖顺序形成可审查检查点，每次进行相应验证、提交并推送，同步 README。当前先整理自动化核心与反馈一致性，再推进持久存储、配置／导入、运行时及阶段 E 接入。每个提交只包含明确范围，其他工作区资料保留。

现场约束：EA-5 配置与控制范围保持不变。阶段 E 不包含阶段 F 的正式部署、72 小时运行或阶段 G 的整屋接管；现场验收需要单独安排。当前阶段 E 未完成。
