# 灯光状态与面板 LED 联动

开关采用当前连接代次的新鲜读回状态；Dimmer 采用 HomeSense 已完整写出的设定。HomeSense 设定并不表示硬件已达到该亮度，总线反馈继续保留用于诊断。尚无本地设定时暂用反馈显示，首次成功写出后设定优先。组合调光灯的供电继电器也是开关：继电器读回关闭时，逻辑灯关闭并保留重新开启的亮度。

HAP 的读取和事件使用相同投影。Web 返回 `observed` 实际组合反馈、`reported` 控制状态和 `state_authority`；管理页采用 `reported`，设定与反馈不同则同时显示读回亮度。未知或过期反馈仍使状态不可用，本地记录不能延长反馈有效期。普通自动化的实际反馈条件、原始反馈缓存及场景 Activity 诊断保持独立。

## 持久记录

schema 21 的 `light_setting` 保存每个配置版本／设备最后完整写出的调光设定，包含 0%。设定更新与命令 Written 审计在同一事务中提交。排队、取消、失败和不确定写入不更新设定。schema 20 迁移只引入可证明完整写出的历史目标；已经标记不确定的旧历史不推断恢复。重启保留设定但不重放命令；非零恢复亮度仍单独保存。

配置版本隔离设定。数据库升级前需保留一致性备份，旧程序不能直接打开 schema 21。此检查点使用 schema 22；当前软件为 schema 24，备份检查支持 schema 18–24，最近限定现场仍为 schema 22。数据库版本与现场验收范围见[阶段 E 跟踪](stage-e-progress.md)。

## 联动配置

自动化文档可增加 `indicator_links`，默认不启用。例如以下通用片段将同一场景关联两个面板 LED：

```json
{"indicator_links":[{
  "id":"reading-indicators",
  "enabled":true,
  "review_evidence":"已核对灯光范围和两个面板的指示键",
  "scene":"reading",
  "lights":["main-light","spotlights"],
  "leds":["panel-a:key:1","panel-b:key:3"]
}]}
```

`scene` 必须是已审核互斥组的成员，`lights` 必须完整覆盖该场景的灯光作用范围。运行时按时间和源顺序取各灯的最终目标：**原本应亮的任意一路关闭，就取消该场景并关闭全部关联 LED**。目标为关或 0% 的灯不参与取消判断。例如节能场景原本关闭主灯、筒灯 17%，主灯关闭不会取消节能，筒灯关闭才会取消。

只清除匹配的本地选择值，不运行场景的物理关闭序列；其他仍亮的灯继续保持现状。未启用场景对账时，尚未确定的选择保持未知，已审核的 LED 关闭照常执行。启用经审核的 `unique_light_on_pattern` 对账后，每次启动／重连由当前连接的新鲜、完整、无未决输出反馈重新建立选择：全组灯光明确全关则为 0，开／关组合唯一匹配一个成员则为该成员，歧义、缺失或过期保持未知；亮度单独显示，不要求与场景目标精确相等。此本地选择不建立 EA-5 独立变量的 toggle 基线。无 `scene` 的单灯／灯组链接在列出的灯全部关闭时联动 LED。

同一灯可出现在多个链接，同一链接可包含多个面板 LED。单个 LED 在启用链接中要求唯一归属，冲突需要先合并明确语义；不同场景共享同一指示键的候选不能未经核查同时启用。LED 绑定须启用且配置为手动模式。配置上限为 128 条链接，每条最多 64 路灯和 64 个 LED。

运行时使用反馈租约、连接代次及变量 CAS，待发送命令和新反馈之间仍有竞争时不提交。当前保守地等待所有活跃场景／软件渐变结束，再核对关闭；不会把启动时旧反馈或缺失反馈当成关闭。一个可确认的应亮负载关闭足以取消场景，其他未知负载本身不构成关闭证据。TS6 的 LED 关闭命令表示退出红色选择指示、恢复绿色，不改变自动背光模式。持续关闭只成功接受一次 LED 联动；明确未接受的队列暂满、反馈租约变化或变量 CAS 冲突，不计为成功／不确定尝试，下一轮用新快照重新规划。读取接口暂忙时延期，不因此退出统一服务。提交等待前保留尝试标记，只有收到明确拒绝才恢复旧标记；响应丢失、等待被取消或其他不确定结果不逐次轮询重发，需新的状态边沿或新的场景选择才能再次尝试。

## 推断选择的联动边界

LED 联动通过专用进程内入口读取当前作用域的选择和来源。普通自动规则继续遮蔽推断值。未改变的选择作为事务内只读版本条件，与 LED 命令共同提交；不推进变量版本，不复制推断数字为本地意图。匹配场景被熄灯取消时才写入 0，其他选中成员保持原值及 inferred 来源。

接受前重新核验来源和流代次；若来源已失效或变量已被人工更新，整批拒绝，变量与 LED 收据均不提交。对当前推断，按键前或同毫秒的样本在规划时视为未知；它们不能单独授权关闭，也不否决另一路独立新鲜 Off。Dimmer 持久 0% 还须来自同一 boot 的按键之后完整写出；旧记录不因新查询成为新关闭证据，实际供电继电器读回关闭仍按开关处理。旧 Dimmer 零值在条件中也视为未知，不能阻断另一开关的有效部分熄灯。反馈租约和未决输出检查继续保留，不能宣称固定响应延迟。

联合回归覆盖部分熄灯、多面板联动、另一推断成员来源保留、旧反馈、流失效、人工选择竞争和持久零值时间边界。只使用合成数据，不改变 EA-5 或启用现场观察配置。

## Control4 核查与现场范围

原项目中同一场景可从多个面板入口触发；每个入口的 LED 集合并不总相同。核查必须保留入口和条件，关闭关联集合应覆盖已确认的多个面板，不能把相邻的“重置其他场景 LED”命令误认成当前场景的指示灯。

具体家庭绑定、源指纹、入口差异和候选修正集合保留本地，不提交公开仓库。书房三场景的候选配置已加入关闭联动；其余差异仍需绑定／现场确认，继续禁用。EA-5 配置、控制范围和面板程序保持不变；HomeSense 面板自动触发规则未开启。

外部按键观察使用独立候选集合；本地 LED 清零不会改写该集合。下一次同键依外部集合切换，不因本地已变成 0 而错误地推断开启。历史初始全关回归属于未启用本地场景对账的策略，选择仍为 NULL、版本不变，同时只发送明确关联的 LED Off；不替代上面的已审核对账策略。`b31ddeb` 的原生场景与 LED 同步六项联合软件验证已通过：相对操作 pending 时只暂缓其关联组，组合灯的供电／条件调光／最终完整查询各阶段不提前清 LED，独立负载链接仍可联动；取快照后的新操作由原提交门禁拒绝旧 LED 计划。见[联合根核查](evidence/stage-e-browser/native-relative-indicator-joint-root-check.json)。真实多面板和启动现场验收仍挂起。
