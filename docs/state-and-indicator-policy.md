# 灯光状态与面板 LED 联动

开关和稳定的 Dimmer 采用当前连接代次的新鲜实际反馈。灯确认开启、实际读回 17% 时，显示 17%，历史完整写出的 100% 不能永久覆盖它。组合调光灯的供电继电器读回关闭时，逻辑灯关闭；此时调光模块内部非零读数不能作为发光亮度或新的恢复偏好。历史写出设定继续作为意图审计保存，不是当前物理真值。

HAP 读取、事件和 Web `reported` 使用同一显示契约。真正本地待决／渐变目标绑定接受命令 ID 集合、完整连接／配置／控制代次和最长 16 秒窗口；接受、正在写出或已写出等待落定时可保护目标，完整写出后的新鲜匹配反馈使目标完成。取消、失败、不确定、收据缺失、换代或到期使目标失效。单一 HAP Brightness 在此有界窗口保护目标以避免滑块回跳；Web 同时返回 `observed` 实际反馈、`reported` 和 `state_authority=pending_target`，可区分目标与当前读回。稳定状态的 `reported` 与实际相同，权威为 `feedback`。未知或过期反馈仍使状态不可用，本地记录不能延长反馈有效期。普通自动化的实际反馈条件、原始反馈缓存及场景 Activity 诊断保持独立。

## 持久记录

`light_setting` 保存每个配置版本／设备最后完整写出的调光设定，包含 0%，仅用于意图／历史诊断。设定更新与命令 Written 审计在同一事务中提交。排队、取消、失败和不确定写入不更新设定。历史设定仅保留可证明完整写出的目标，不确定记录不能推断为恢复偏好。重启保留历史设定但不重放命令，也不重建旧的待决窗口；非零恢复偏好单独保存。稳定开启时，新鲜、落定的实际 17% 可更新恢复偏好为 17%。Off 不清空偏好；下一次单独开灯恢复 17%。正在本地渐变的中间样本和写前／未落定样本不写入偏好，恢复记忆的读取和保存都不能用旧历史设定代替实际反馈。关灯时 HAP Brightness 可保留恢复偏好，Power=false 和实际发光亮度 0 保持分开。

配置版本隔离设定，数据库升级和回退使用匹配程序与一致性备份，见[完整状态回退](state-upgrade-rollback.md)。

## 联动配置

自动化文档可增加 `indicator_links`，默认不启用。例如以下通用片段将同一场景关联两个面板 LED：

```json
{"indicator_links":[{
  "id":"reading-indicators",
  "enabled":true,
  "review_evidence":"已核对灯光范围和两个面板的指示键",
  "scene":"reading",
  "lights":["main-light","spotlights"],
  "leds":["panel-a:key:1","panel-b:key:3"]
}]}
```

`scene` 必须是已审核互斥组的成员，`lights` 必须完整覆盖该场景的灯光作用范围。运行时按时间和源顺序取各灯的最终目标：**原本应亮的任意一路关闭，就取消该场景并关闭全部关联 LED**。目标为关或 0% 的灯不参与取消判断。例如节能场景原本关闭主灯、筒灯 17%，主灯关闭不会取消节能，筒灯关闭才会取消。

只清除匹配的本地选择值，不运行场景的物理关闭序列；其他仍亮的灯继续保持现状。未启用场景对账时，尚未确定的选择保持未知，已审核的 LED 关闭照常执行。启用经审核的 `unique_light_on_pattern` 对账后，每次启动／重连由当前连接的新鲜、完整、无未决输出反馈重新建立选择：全组灯光明确全关则为 0，开／关组合唯一匹配一个成员则为该成员，歧义、缺失或过期保持未知；亮度单独显示，不要求与场景目标精确相等。此本地选择不建立 EA-5 独立变量的 toggle 基线。无 `scene` 的单灯／灯组链接在列出的灯全部关闭时联动 LED。

经审核启用场景对账的链接采用完整当前物理选择：唯一匹配的成员所有关联 LED 设红，其余成员设绿；全关为全绿。正向输出必须具有同一快照的完整、同 boot／epochs 的物理选择、反馈租约和未决检查，不能从历史变量或 EA-5 变量猜测。未知、缺失、过期、相对操作 pending 或覆盖该链接的本地待决目标不授权抢写；记录接受尝试后不按轮询重发。LED 同步只输出配置已启用链接内的 PanelLed，不执行灯光／场景动作、不启用外部按键 observer、不改写历史选择。

普通灯链接的 Off 条件也使用当前实际反馈；历史非零值不能阻止新鲜实际 Off 清 LED，历史零值不能使实际 On 被误清。已有显式内部兼容规划接口可以接收历史值，但生产同步路径不再传入它们作为物理条件覆盖。

同一灯可出现在多个链接，同一链接可包含多个面板 LED。单个 LED 在启用链接中要求唯一归属，冲突需要先合并明确语义；不同场景共享同一指示键的候选不能未经核查同时启用。LED 绑定须启用且配置为手动模式。配置上限为 128 条链接，每条最多 64 路灯和 64 个 LED。

运行时使用反馈租约、连接代次及变量 CAS，待发送命令和新反馈之间仍有竞争时不提交。当前保守地等待所有活跃场景／软件渐变结束，再核对关闭；不会把启动时旧反馈或缺失反馈当成关闭。一个可确认的应亮负载关闭足以取消场景，其他未知负载本身不构成关闭证据。TS6 的 LED 关闭命令表示退出红色选择指示、恢复绿色，不改变自动背光模式。持续关闭只成功接受一次 LED 联动；明确未接受的队列暂满、反馈租约变化或变量 CAS 冲突，不计为成功／不确定尝试，下一轮用新快照重新规划。读取接口暂忙时延期，不因此退出统一服务。提交等待前保留尝试标记，只有收到明确拒绝才恢复旧标记；响应丢失、等待被取消或其他不确定结果不逐次轮询重发，需新的状态边沿或新的场景选择才能再次尝试。

## 推断选择的联动边界

LED 联动通过专用进程内入口读取当前作用域的选择和来源。普通自动规则继续遮蔽推断值。未改变的选择作为事务内只读版本条件，与 LED 命令共同提交；不推进变量版本，不复制推断数字为本地意图。匹配场景被熄灯取消时才写入 0，其他选中成员保持原值及 inferred 来源。

接受前重新核验来源和流代次；若来源已失效或变量已被人工更新，整批拒绝，变量与 LED 收据均不提交。对当前推断，按键前或同毫秒的样本在规划时视为未知；它们不能单独授权关闭，也不否决另一路独立新鲜 Off。实际反馈必须满足当前租约、同代次及后按键时间边界。持久 Dimmer 零值／非零值本身均不授权或否决物理 Off；旧记录不因新查询成为新关闭证据，实际供电继电器读回关闭仍按开关处理。反馈租约和未决输出检查继续保留，不能宣称固定响应延迟。

## Control4 核查与现场范围

原项目中同一场景可从多个面板入口触发；每个入口的 LED 集合并不总相同。核查必须保留入口和条件，关闭关联集合应覆盖已确认的多个面板，不能把相邻的“重置其他场景 LED”命令误认成当前场景的指示灯。

具体家庭绑定、源指纹、入口差异及运行日志留在私有目录。完整接管与既有验收范围见[结项清单](control4-takeover-checklist.md)，不把配置声明或最后写出颜色当作物理 LED 读回。
