# 共享供电与复用调光列

`shared_lights` 是设备配置中的显式、可选分组，用于两盏共用供电的灯，其调光列还被另外两组床头灯复用。它不修改普通组合灯的独占供电规则，也不根据显示名推断接线。

每组登记六个现有物理设备 ID：`common_supply`、`left_supply`、`right_supply` 三路供电，以及 `primary`、`secondary`、`reading` 三路调光。六路必须启用、互不重复、处于同一网关和房间，且不能同时属于其他共享组或独占组合灯。分组需要明确的 `review_evidence`；调光输出保留显式非零默认开启亮度。

## 独立控制

原生设备命令入口对 `primary`、`secondary` 使用共享规划：

- 关闭只将目标调光列归零；另一盏仍亮时保留公共供电。
- 开启时保留另一盏的实际亮度。供电关闭时的非零调光寄存器不能作为灯亮的证据；先清除这类残留值，再接通公共供电。
- 操作 `primary` 退出两侧床头供电。
- 操作 `secondary` 时，若阅读调光和至少一侧阅读供电实际开启，保留阅读调光及现有床头供电；对应的中间灯随共享调光列变化。关闭 `secondary` 也保留阅读。
- 夜灯独立运行、阅读未开启时，操作 `secondary` 先退出床头供电，再控制目标灯。

准入需要六路当前反馈、完整依赖权限及仍有效的来源凭证。反馈变化、过期、存在未完成的依赖写入或运行代次改变时，整批拒绝，不按旧状态重放。各物理写入保留既有日志和失败处理；整批准入不等于总线具有原子事务。

## 状态与原有程序

日常状态将两盏公共供电灯投影为“供电开启且对应调光非零”。亮度恢复同样使用供电门控后的实际值，床头夜灯使用的调光值不能覆盖主灯恢复亮度。原始反馈不改写；既有自动化仍按明确的物理配方执行。

原生设备入口、六键场景状态和 LED 已在本机 TLS/TCP 回环中联合验证，Linux及现场验收尚未完成，未部署。未携带共享反馈租约的普通手动批次会拒绝这两路逻辑目标，不能用裸命令绕过规划；尚未为这类分组开放 HAP 写入。物理模块管理、场景与卡片的最终展示范围需要随具体发布配置核对。

隔离回环不证明 RS485 上的无冲突收发，也不替代现场接线与全屋验收。

## 场景选择与独立灯光混用

共享供电下，另一盏灯变化不能清除仍在工作的阅读灯身份。需要保留模式意图的程序可在 `program_confirmation` 中显式登记 `recorded_selection`，列明允许更新该选择的 `source_scenes`、代次切换时归为未知的 `reset_variables` 和审核依据。这些变量不能再同时配置物理模式推断。启动、配置或运行代次变化，以及相关网关失联时，旧选择会归为未知。

选择值只表达意图。场景显示开启仍要求对应程序的实际写入、完整批次反馈和持续有效的正向灯光证据；单独保存一个选择值，或重启后恰好读到相同灯光组合，都不能重建开启状态。当前真实反馈可证明某个场景未开启，但这个只读判断不改变量、不查询总线，也不授予切换权限。

公共供电下的两盏独立灯使用各自的实际供电与调光反馈显示状态。对应 LED 可显式配置 `power_policy: follow_all_on`：全部目标已知时，全部开启显示红色，否则显示绿色；未知时不写颜色。`clear_if_any_off` 只在已知条件失配时清绿，不根据灯光组合点红模式键。两种策略沿用反馈租约、未完成写入屏障和 LED 输出版本检查，不能重放未确认的写入。未登记此策略的既有 LED 链接保持原行为。
