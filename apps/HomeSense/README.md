# HomeSense App

SwiftUI 家庭控制与配置工具，支持 iPhone / iPad（iOS / iPadOS 17+）和 Mac Catalyst（macOS 14+）。

## 功能入口

| 入口 | 用途 | 连接与权限 |
| --- | --- | --- |
| 家庭 | 按房间或类别浏览配件，控制灯光、开关、风机、窗帘并查看传感器与家庭场景 | 系统 HomeKit，使用 Apple「家庭」授权 |
| 配置管理 | 编辑楼层、房间、设备、面板与场景，管理草稿、发布配置和读取模块诊断 | HomeSense HTTPS 服务及访问令牌，管理操作需要管理员权限 |
| 本地调试 | 通过透明串口网关查询面板、修改地址、测试指令并查看通信日志 | 手动建立 TCP 连接并明确发送指令 |

## 家庭

### 首次使用

1. 在 Apple「家庭」中添加桥接器或兼容配件，完成家庭与房间设置。
2. 打开 HomeSense，允许访问家庭，选择要使用的家庭；系统询问本地网络权限时允许访问。
3. 按房间或“温控、灯、安防、窗帘、开关、传感器”类别浏览配件。iPad 和 Mac 使用侧栏，iPhone 通过“房间”入口切换。

家庭页面使用 HomeKit 读取和订阅状态，也能显示其他厂商加入该家庭的兼容配件。日常控制无需填写 HomeSense 服务端令牌；可见范围、控制和改名权限由 Apple「家庭」决定。

### 浏览与控制

点配件名称或状态打开详情；点已知开关状态的图标可快捷开关，状态未知时进入详情。家庭中设置的场景可直接执行，HomeSense 发布的场景开关按其开关状态操作。

| 类型 | 操作方式 |
| --- | --- |
| 调光灯 | 黄色竖向调光条：按点击位置选择最近的 10% 档位，上下拖动按 1% 调节，向上增加亮度，松手提交一次 |
| 开关灯、风机、开关 | 快捷开关或进入详情明确开启、关闭；风机按配件提供的能力显示控制项 |
| 窗帘 | 横向比例条：向右增加打开比例、向左减少；点击选择 10% 档位，拖动按 1% 调节；另有打开、停止、关闭按钮 |
| 传感器 | 查看温度、湿度、接触、运动、电量等配件提供的真实读数；同一配件的相关读数组合展示 |

调光和窗帘拖动优先于页面滚动。目标值与实际读回分开显示，等待反馈期间目标不会被中间读数拉回；窗帘停止按钮独立可用。进入前台或切换家庭时读取状态，随后通过系统通知更新；不可达或未知状态会明确显示，控制失败不会自动重发。

### 常用、隐藏、排序与改名

- **常用配件**：长按或右键卡片，选择加入常用或取消常用。
- **隐藏配件**：长按卡片选择“隐藏配件”；右上角菜单 →“隐藏配件”可逐项恢复或恢复全部，也可统一隐藏名称以“灯带”开头的配件。名称规则适用于新加入的匹配配件，支持单独恢复例外。
- **房间排序**：右上角菜单 →“房间排序”，拖动手柄调整顺序，家庭页与房间列表使用相同顺序；“恢复默认顺序”按名称排列。房间改名后保留顺序，新房间追加在末尾。
- **配件改名**：详情齿轮 →“名称”，保存后由 HomeKit 同步到其他 Apple「家庭」客户端；需要家庭编辑权限。

常用、隐藏和房间顺序按家庭保存在本机，重开 App 后保留，各台设备独立设置。隐藏配件不参与页面数量与状态汇总，恢复显示时保留常用标记；这些显示设置不会改变设备、场景或墙面板的控制规则。

## 配置管理

### 服务连接

进入“配置管理 → 服务连接”，输入服务的完整 HTTPS Origin（例如 `https://<服务域名>:<端口>`）和访问令牌，点击“连接 HomeSense”。证书须受系统信任且与服务地址匹配。

鉴权成功后，凭证按服务地址与端口保存在本机系统 Keychain，不参与 iCloud 同步。进入配置管理时可恢复连接，也可选择“使用此服务已保存的凭证连接”。“断开服务”结束当前连接；“退出并移除本机凭证”同时清除本机保存项，不撤销服务端令牌。

配置管理通过实时推送接收服务端状态。网络恢复后重新同步，不重放先前的控制或发布操作。

### 编辑与发布

管理员可编辑楼层、房间、逻辑设备、面板与按键用途、场景配方和房间归属。

1. 在对应页面编辑，或进入“草稿与发布 → 逻辑设备配置”编辑完整逻辑设备。
2. 保存为服务端草稿。
3. 预览校验结果与变更影响，处理错误和版本冲突。
4. 核对后明确确认发布。

保存和预览不改变活动配置。编辑权限、设备绑定、面板用途与发布检查由服务端执行；发生版本冲突时重新读取并核对草稿。

### 模块诊断

“配置管理 → 设备”同时保留六键面板卡片和 DIN 模块卡片。面板卡片显示已发布的按键名称、状态及反馈，点击操作仍使用已有的服务端授权和按键配方；不会因为展示卡片而直接连接485网关。“家庭”页的日常配件仍使用HomeKit。

“设备”页展示 R818-DIN、AD8-DIN 和 C4-DIN 等物理模块及十六进制地址。R818 / AD8 卡片显示八路确认状态，AD8 同时显示亮度读回；没有确认反馈的通道显示未知。读取服务端模块清单不会额外触发总线查询。

模块“设置与测试”按服务端能力与权限提供明确的查询、开关、调光和窗帘操作。每次点击提交一次请求，写出结果与实际反馈分开显示；供电测试仍遵守逻辑组合灯的约束。

## 完整配置草稿

完整设备与自动化草稿支持最多 4 MiB 的保存请求。读取时保留整数精度和原配置字段，两份文档均解析成功后才替换编辑稿；单项 JSON 编辑上限为 256 KiB。

保存、重新读取和预览均不发布草稿。完整配置与单项编辑使用相同的管理员权限、所有者及版本检查，发布仍需明确确认。

## Apple 家庭房间归属

将 HomeSense 发布的配件分配到 Apple「家庭」房间：

1. 先在 Apple「家庭」添加 HomeSense 桥，再以管理员连接“配置管理”。
2. 在“服务连接 → Apple家庭房间归属”中选择“读取Apple家庭并授权”。
3. 选择家庭，点击“读取发布清单与房间”，对应服务器桥与 Apple「家庭」中的桥。
4. 为各目标房间选择已有房间或创建房间；为“未归属／全屋场景”指定目标房间。
5. 点击“预览房间归属”，核对迁移数、原归属正确数、新建房间及待处理项。
6. 确认无误后点击“应用…项房间归属”，查看完成结果。

迁移中断时重新读取并预览，已到位的配件会跳过。切换家庭或配置版本后需要重新预览。

## 本地调试

### 网关连接

在“本地调试 → 网关连接”填写透明串口网关的主机地址与 TCP 端口。网关串口参数应与设备一致；TS6 面板使用 9600、8N1。TCP 连通与设备回复分别显示。离开本地调试或进入后台时断开本地连接。

工具只执行明确选择的指令，不自动扫描总线。调试时避免其他程序同时向该总线发送命令。

### TS6 面板

1. 在“面板地址”输入两位**十六进制**当前地址并查询。未知地址时，仅在确认总线隔离为单面板后使用 `00` 广播查询。
2. 改址选择未占用的 `01–FF`，长按实体按键①并确认发送；随后查询新地址核对。
3. 在“指令测试”查询参数或固件，或明确发送 LED、背光、声音等支持的命令。手动 LED 控制需要面板处于接受指令的模式。
4. 启用“按键联动 LED”时先将六键设绿，每次实体按下切换同键红／绿，释放不切换。断线、后台或切换目标会停止联动，重连后需重新启用。

单字节 `00` 是有效地址读回；写出成功不代表改址或 LED 实物状态已确认。协议实现见 [TS6Protocol.swift](Sources/HomeSenseCore/TS6Protocol.swift)。

### LH-IO1600 地址

1. 连接串口参数一致的透明网关，进入“LH-IO1600 地址”，输入**十进制**当前从站地址后“读取地址”。
2. 未知地址时，先隔离为单模块，再确认使用 `254 / FE` 广播查询；当前地址为 `0` 也要求隔离。
3. 单模块隔离后，选择未占用的十进制新地址 `1–247`，确认发送；此型号无需长按 TS6 面板按键。
4. 点击“查询新地址核对”，以新地址读回相同软件地址后确认成功。

该工具使用带 CRC 的 Modbus RTU 透明传输，不自动操作继电器或修改服务端配置。TS6 与 LH-IO1600 使用各自独立的地址格式和操作流程。

## 诊断日志

“配置管理 → 服务连接 → 导出诊断日志”可导出当前与上一会话的管理请求诊断记录。操作 ID、请求 ID、结果和耗时可用于对照服务端记录；日志不包含访问令牌、服务地址或请求／响应全文，也不代替设备实际反馈。

“本地调试 → 通信日志”保留最近 600 条收发记录，可导出文本。原始通信日志可能包含设备地址与报文，分享前应核对内容。

## 构建与运行

使用 Xcode 打开 `HomeSense.xcodeproj`，选择 `HomeSense` scheme 和 iPhone、iPad 或 My Mac (Mac Catalyst)。配置自己的开发团队，并为明确的 App ID `com.ngboss.homesense` 启用 HomeKit capability、配置相应描述文件。真机仍需用户授权家庭访问。

本机签名设置可写入已忽略的 `Signing.local.xcconfig`。签名私钥、描述文件、访问令牌及安装校验报告不入库。

以下命令在开发本机执行，统一复用仓库根目录 `target/`：

```sh
cd apps/HomeSense
export HOMESENSE_BUILD_ROOT="$(cd ../.. && pwd)/target"

# Debug 构建检查；iOS 与模拟器构建不签名。
bash tools/build.sh macos
bash tools/build.sh ios
bash tools/build.sh simulator

# Swift 测试。
swift test --build-system native --scratch-path "$HOMESENSE_BUILD_ROOT/swift"
```

真机 Release 构建可使用 Xcode，或在完成签名配置后执行：

```sh
xcodebuild -project HomeSense.xcodeproj -scheme HomeSense \
  -destination 'generic/platform=iOS' -configuration Release \
  -derivedDataPath "$HOMESENSE_BUILD_ROOT/ios" \
  DEVELOPMENT_TEAM='<团队ID>' CODE_SIGN_STYLE=Automatic build
```

构建需要完整 Git 历史，并自动记录提交号、源码修改标记与源码指纹。`tools/package-ios.py` 提供安装包签名与校验，使用 `--help` 查看参数；校验覆盖内嵌可执行文件、团队、描述文件和 HomeKit 权限。安装后启动 App 核对授权与连接。

实际 Rust HTTPS/WSS 集成测试需指定固定的本机后端制品；未提供环境变量时，相应测试会明确跳过：

```sh
export HOMESENSE_TEST_BINARY="/absolute/path/to/pinned/homesensed"
export HOMESENSE_KEYPAD_TEST_BINARY="$HOMESENSE_TEST_BINARY"
export HOMESENSE_KEYPAD_TEST_FIXTURES="$PWD/../../config/test/native-app-keypad"
swift test --build-system native --scratch-path "$HOMESENSE_BUILD_ROOT/swift"
```

测试使用隔离模拟设备、临时状态和内存凭证，不访问用户 Keychain。测试与模拟器仅在开发本机运行。
